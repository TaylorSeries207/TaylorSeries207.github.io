Module 1: Main Method & Output

Conceptual Explanation & Architectural Mechanics

Java is a strictly object-oriented, statically typed language that executes within the Java Virtual Machine (JVM). Unlike scripting languages that execute top-to-bottom without strict boilerplate, every Java application requires an explicit structural hierarchy. At the top of this hierarchy sits the class container, and inside it, the static entry-point method.

When you run a Java program, the JVM loads the specified class bytecodes into memory and searches for the exact method signature: public static void main(String[] args). Understanding each keyword of this entry point is vital for writing bug-free code and avoiding runtime errors:

  • public: The access modifier specifying that the method can be invoked from outside its class package by the JVM execution engine.
  • static: Indicates that the method belongs to the class itself rather than an instantiated object instance. This allows the JVM to launch the program without allocating object memory beforehand.
  • void: The return type keyword declaring that this method does not return any value back to the caller upon completion.
  • main: The reserved method identifier recognized globally by JVM implementations as the initial thread start location.
  • String[] args: An array of String references designed to capture command-line arguments passed into the application upon startup.

Output operations in standard Java are handled via the system-defined I/O streams. The call System.out.println() routes data through the standard output stream (out), appended automatically with a platform-dependent newline character sequence (\n or \r\n). In contrast, System.out.print() outputs raw character data without advancing the cursor to the subsequent line. Escape sequences such as \n (newline), \t (tab insertion), and \" (double quote escaping) provide fine-grained formatting control within string literals.

Online Judge (DMOJ/USACO) Strict Requirement:
In competitive programming platforms like DMOJ or USACO, your public class name must be named Main when submitted in a single file environment. If your file contains public class Solution, the judge will reject it with a compilation error.

public class Main {
    public static void main(String[] args) {
        // Standard output with automatic line advancement
        System.out.println("Welcome to STEM & AI Academy Java Course!");
        
        // Outputting formatted strings using print vs println
        System.out.print("Item\t\tQty\tPrice\n");
        System.out.print("----------------------------------\n");
        System.out.print("Robotics Kit\t1\t$299.99\n");
        System.out.print("Sensors\t\t4\t$45.50\n");

        // Escape sequences demonstration
        System.out.println("She said, \"Java requires exact syntax matching!\"");
    }
}

Module 2: Primitive Types & Math

Conceptual Explanation & Architectural Mechanics

Data representation in Java is strictly divided into two categories: primitive types and reference types. Primitive types store raw binary values directly in stack memory, providing predictable performance and minimal memory overhead. Java defines exactly eight primitive types, with integer arithmetic defaulted to int and decimal arithmetic defaulted to double.

Understanding memory allocations and bit ranges is crucial for algorithm design and avoiding catastrophic silent overflows:

  • byte: 8-bit signed integer (\([-128, 127]\)).
  • short: 16-bit signed integer (\([-32768, 32767]\)).
  • int: 32-bit signed integer (\([-2^{31}, 2^{31}-1]\) or roughly \([-2.14 \times 10^9, 2.14 \times 10^9]\)).
  • long: 64-bit signed integer (\([-2^{63}, 2^{63}-1]\) or roughly \([-9.22 \times 10^{18}, 9.22 \times 10^{18}]\)). Literal constants require an L suffix (e.g., 10000000000L).
  • float: 32-bit IEEE 754 floating-point (requires f suffix, e.g., 3.14f).
  • double: 64-bit IEEE 754 floating-point (15–17 decimal digits precision).
  • char: 16-bit unsigned Unicode character (\([0, 65535]\)).
  • boolean: Logical truth value (true or false).

When arithmetic operations involve mixed operand types, Java automatically performs Numeric Type Promotion. Smaller integer types (byte, short, char) are promoted to int before evaluating arithmetic expressions. If any operand is long, float, or double, the entire expression is promoted to that larger type.

For high-level mathematical operations, Java provides the built-in Math class within java.lang. Key static methods include Math.abs(), Math.max(), Math.min(), Math.pow(base, exp), and Math.sqrt(). Note that Math.pow() and Math.sqrt() return values of type double, requiring explicit casting if an integer result is needed.

Integer Overflow Trap:
In competitive programming, multiplying two large int values before assigning them to a long variable will still overflow because the multiplication evaluates as an int first. Fix this by explicitly casting one factor: long result = (long) a * b;.

Student Hands-on Code

public class Main {
    public static void main(String[] args) {
        // Integer overflow demonstration and fix
        int a = 1000000;
        int b = 1000000;
        int overflowResult = a * b; // Result is -727379968 due to 32-bit wrap
        long correctResult = (long) a * b; // Properly promoted to 64-bit calculation

        System.out.println("Overflowed Int Result: " + overflowResult);
        System.out.println("Correct Long Result:   " + correctResult);

        // Standard Math Library usage
        double radius = 7.5;
        double area = Math.PI * Math.pow(radius, 2);
        double hypotenuse = Math.sqrt(Math.pow(3, 2) + Math.pow(4, 2));

        System.out.println("Circle Area: " + area);
        System.out.println("Hypotenuse (3, 4): " + hypotenuse);

        // Casting float/double to integer
        int roundedInt = (int) Math.round(area);
        System.out.println("Rounded Area to Nearest Int: " + roundedInt);
    }
}

Module 3: String Operations

Conceptual Explanation & Architectural Mechanics

Unlike primitive types, a String in Java is an immutable reference object defined in java.lang.String. Immutability means that once a String instance is instantiated on the heap memory, its character sequence cannot be altered in-place. Any operation that appears to mutate a String—such as concatenation or case modification—actually creates a completely new String object in memory and updates the reference variable.

To optimize memory usage, Java utilizes a String Constant Pool inside the heap. String literals (e.g., "hello") are automatically stored in the pool. If another literal with the exact same sequence is declared, Java reuses the existing reference rather than allocating new memory.

Because Strings are objects, comparing them using the relational operator == tests whether two reference variables point to the exact same memory address (reference equality). To compare the actual character contents, you must always use .equals() or .equalsIgnoreCase().

Essential String methods for string manipulation and parsing include:

  • .length(): Returns the integer character count.
  • .charAt(int index): Returns the char value at the specified 0-based index.
  • .substring(int beginIndex, int endIndex): Extracts a string slice from beginIndex up to, but excluding, endIndex (\([begin, end)\)).
  • .indexOf(String str): Returns the 0-based index of the first occurrence of str, or -1 if not found.
  • .toUpperCase() / .toLowerCase(): Returns a new string with transformed casing.
Reference Equality vs Value Equality:
Writing str1 == str2 is a classic beginner bug. If str1 is created via input and str2 is a literal, == evaluates to false even if both contain "hello". Always write str1.equals(str2).

Student Hands-on Code

public class Main {
    public static void main(String[] args) {
        String msg1 = "Java Programming";
        String msg2 = new String("Java Programming");

        // Reference vs Value comparison
        System.out.println("Using == operator: " + (msg1 == msg2)); // false (different objects)
        System.out.println("Using .equals():   " + msg1.equals(msg2)); // true (same content)

        // Inspection and Substrings
        int len = msg1.length();
        char firstChar = msg1.charAt(0);
        String word = msg1.substring(0, 4); // "Java"

        System.out.println("Length: " + len + ", First Char: " + firstChar);
        System.out.println("Extracted Substring: " + word);

        // Searching and Transformation
        int pos = msg1.indexOf("Grammar"); // Returns -1 (not found)
        int pos2 = msg1.indexOf("Prog");   // Returns 5
        String loud = msg1.toUpperCase();

        System.out.println("Position of 'Prog': " + pos2);
        System.out.println("Transformed: " + loud);
    }
}

Module 4: Scanner Input & If-Else

Conceptual Explanation & Architectural Mechanics

Interactive program execution relies on parsing standard input streams. The Scanner class, residing within java.util, provides convenient token-based parsing for reading primitive types and strings from System.in. A Scanner breaks input into tokens separated by delimiter patterns (defaulting to whitespace characters such as spaces, tabs, and newlines).

Common parsing methods include nextInt(), nextDouble(), nextLong(), next() (reads the next single word token), and nextLine() (reads the entire input buffer until a newline character is encountered).

Decision making and branching are driven by boolean logic evaluation inside if, else if, and else blocks. Relational operators (>, <, >=, <=, ==, !=) yield primitive boolean results. Logical operators allow complex compound condition evaluation:

  • && (Logical AND): Evaluates to true if and only if both operands are true. Uses short-circuiting.
  • || (Logical OR): Evaluates to true if at least one operand is true. Uses short-circuiting.
  • ! (Logical NOT): Inverts a boolean truth value.
The Infamous Scanner Bug: nextInt() followed by nextLine()
When calling nextInt(), Scanner reads the integer token but leaves the trailing newline character (\n) sitting in the input buffer. If you immediately call nextLine(), it consumes that leftover newline and returns an empty string! Fix: Place a dummy scanner.nextLine(); directly after nextInt() to clear the buffer.

Student Hands-on Code

import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        System.out.print("Enter student age: ");
        int age = scanner.nextInt();

        System.out.print("Enter test score (0-100): ");
        double score = scanner.nextDouble();

        // Clearing leftover newline token from numeric reads!
        scanner.nextLine(); 

        System.out.print("Enter student name: ");
        String name = scanner.nextLine();

        // Conditional branching with logical evaluation
        if (score >= 90.0 && age >= 12) {
            System.out.println(name + ": Qualified for Advanced Competitive Placement!");
        } else if (score >= 75.0 || age >= 15) {
            System.out.println(name + ": Qualified for Intermediate Java Module.");
        } else {
            System.out.println(name + ": Placed in Foundational Track.");
        }

        scanner.close();
    }
}

Module 5: Fixed Arrays (int[])

Conceptual Explanation & Architectural Mechanics

An array in Java is a dynamically allocated, fixed-length contiguous sequence of elements of the same type. Because arrays store homogeneous data in contiguous memory blocks, access to any random index element occurs in constant time \(\mathcal{O}(1)\) via memory offset calculation: \[\text{Address}(\text{index}) = \text{Base Address} + (\text{index} \times \text{element size})\]

Key properties of Java arrays:

  • Fixed Dimension: Once an array is instantiated (e.g., new int[10]), its size is permanently fixed and cannot grow or shrink.
  • Default Element Initialization: Allocating an array automatically fills its elements with default values: 0 for numeric types (int, double), false for boolean, and null for object references.
  • Zero-Indexed Bounds: Valid indices range strictly from 0 up to array.length - 1. Accessing an index outside this range throws an ArrayIndexOutOfBoundsException at runtime.
  • Length Attribute: The total number of allocated slots is queried via the public read-only property .length (note: field property, no parentheses, unlike String's .length() method).

Arrays can be instantiated directly with values using array literal notation: int[] primes = {2, 3, 5, 7, 11};. To copy array contents safely without creating aliased references pointing to the same memory location, use System.arraycopy() or Arrays.copyOf().

Reference Aliasing Warning:
Writing int[] arr2 = arr1; does not clone the array. It simply copies the memory address reference! Modifying elements in arr2 will directly change arr1. Use int[] arr2 = arr1.clone(); for an independent copy.

Student Hands-on Code

import java.util.Arrays;

public class Main {
    public static void main(String[] args) {
        // Direct allocation with zero-initialization
        int[] scores = new int[5];
        scores[0] = 85;
        scores[1] = 92;
        scores[2] = 78;
        scores[3] = 95;
        scores[4] = 88;

        // Querying length property
        System.out.println("Array Capacity: " + scores.length);

        // Linear scan to compute sum and max value
        int sum = 0;
        int maxVal = scores[0];

        for (int i = 0; i < scores.length; i++) {
            sum += scores[i];
            if (scores[i] > maxVal) {
                maxVal = scores[i];
            }
        }

        double average = (double) sum / scores.length;
        System.out.println("Average Score: " + average);
        System.out.println("Highest Score: " + maxVal);

        // Utility operations via java.util.Arrays
        Arrays.sort(scores);
        System.out.println("Sorted Scores: " + Arrays.toString(scores));
    }
}

Module 6: Methods & Scope

Conceptual Explanation & Architectural Mechanics

Methods are self-contained modular blocks of code that perform specific tasks, accept input parameters, and optionally return results. Implementing methods promotes code reuse, modularity, and readable abstraction.

A standard method declaration consists of modifiers, return type, method name, parameter list, and method body:

public static returnType methodName(parameterType param1, parameterType param2) {
    // Method execution logic
    return value;
}

Understanding Parameter Passing Mechanics in Java is critical: Java is strictly **Pass-by-Value** in all scenarios!

  • Primitive Arguments: A copy of the raw primitive value is passed into the method parameter variable. Modifying the parameter variable inside the method body has zero effect on the caller's original variable.
  • Object & Array Arguments: A copy of the reference memory address is passed into the method. While reassigning the parameter variable itself inside the method won't affect the caller's reference, mutating the internal elements or state of the passed object/array directly mutates the caller's data!

Variable scope dictates where a declared variable can be accessed within code. **Local Variables** declared within a method or code block (e.g., inside an if or for loop) exist only on the execution stack frame while that block is executing, and are garbage collected once execution leaves the enclosing curly braces {}.

Method Overloading:
Java supports defining multiple methods within the same class sharing the exact same name, provided they have different parameter lists (either different parameter count or different data types). Return types alone cannot distinguish overloaded methods.

Student Hands-on Code

public class Main {

    // Overloaded Method 1: Computes area of a square
    public static double computeArea(double side) {
        return side * side;
    }

    // Overloaded Method 2: Computes area of a rectangle
    public static double computeArea(double width, double height) {
        return width * height;
    }

    // Demonstration of array mutation inside methods
    public static void doubleArrayValues(int[] arr) {
        for (int i = 0; i < arr.length; i++) {
            arr[i] *= 2; // Mutates original array in heap memory
        }
    }

    public static void main(String[] args) {
        double squareArea = computeArea(5.0);
        double rectArea = computeArea(4.0, 6.0);

        System.out.println("Square Area:    " + squareArea);
        System.out.println("Rectangle Area: " + rectArea);

        int[] numbers = {1, 2, 3, 4, 5};
        doubleArrayValues(numbers);

        // Verification of pass-by-value reference mutation
        System.out.print("Mutated Array: ");
        for (int num : numbers) {
            System.out.print(num + " "); // Prints 2 4 6 8 10
        }
        System.out.println();
    }
}

Module 7: Debug & NullPointer

Conceptual Explanation & Architectural Mechanics

Software development and algorithmic problem solving require robust debugging strategies and an understanding of runtime exceptions. An exception is an event occurring during program execution that disrupts the normal instruction flow.

The most ubiquitous error encountered in object-oriented Java programming is the NullPointerException (NPE). In Java, any object reference variable that has not been initialized with a heap instance points to null (a special literal signifying an unallocated memory pointer). Attempting to call a method or access an instance field on a null reference crashes the program with an NPE.

To write fault-tolerant code and prevent abnormal application termination, Java provides structured exception handling via try-catch-finally blocks:

  • try block: Encloses code that might potentially throw an exception.
  • catch block: Intercepts and handles specified exception types without crashing the application thread.
  • finally block: Executes unconditionally regardless of whether an exception was thrown or caught, making it ideal for cleaning up resources (e.g., closing file streams or input connections).
Defensive Null-Check Technique:
To avoid NPEs when comparing string variables against literal values, always call the .equals() method on the known non-null literal constant! Write "EXPECTED".equals(inputString) instead of inputString.equals("EXPECTED").

Student Hands-on Code

public class Main {
    public static void main(String[] args) {
        String unsafeText = null;

        // Defensive Null Protection Strategy
        if ("DEMO".equals(unsafeText)) {
            System.out.println("Match found safely!");
        } else {
            System.out.println("Safe comparison executed without NullPointerException.");
        }

        // Exception Handling for Invalid Conversions and Bounds
        String rawInput = "100A"; // Contains non-digit character
        
        try {
            int parsedNumber = Integer.parseInt(rawInput);
            System.out.println("Parsed result: " + parsedNumber);
        } catch (NumberFormatException e) {
            System.err.println("Error: Failed to convert string to numeric int!");
            System.err.println("Details: " + e.getMessage());
        } finally {
            System.out.println("Cleanup / Execution audit complete.");
        }
    }
}

Module 1: Switch & Ternary

Conceptual Explanation & Architectural Mechanics

Conditional control flow often extends beyond simple binary decisions. When evaluating multiple discrete integral or categorical branches, multi-nested if-else structures introduce visual complexity and performance degradation. Java provides optimized branching structures through the switch statement and modern switch expressions, alongside the concise inline ternary operator.

The standard switch statement evaluates a variable against multiple case values. Supported evaluation types include integer primitives (byte, short, char, int), their corresponding wrapper classes, String objects, and enum constants. Under the hood, the Java compiler optimizes switch blocks using two distinct bytecode instructions depending on density:

  • tableswitch: Used when case values are dense (contiguous integers). It performs an \(\mathcal{O}(1)\) direct index jump table lookup.
  • lookupswitch: Used when case values are sparse or non-integer (such as Strings). It uses a sorted key-value binary search table with \(\mathcal{O}(\log N)\) complexity.

Traditional switch blocks require explicit break statements to prevent "fall-through" execution into lower cases. Introduced in Java 12+, modern switch expressions simplify this syntax using arrow labels (->), automatically eliminating fall-through and allowing the block to return a value directly.

The ternary operator (condition ? expression1 : expression2) offers a compact inline alternative for assignment or returning values based on a single boolean condition. However, care must be taken regarding type promotion: the return type of a ternary expression is automatically unified to the broader type of expression1 and expression2, which can lead to implicit casting or unboxing exceptions.

Modern Switch Arrow Syntax:
Using case VALUE -> ... replaces the traditional case VALUE: ... break; syntax. It enforces single-branch execution, prevents accidental fall-through bugs, and allows yield values directly into variable assignments.

Student Hands-on Code

public class Main {
    public static void main(String[] args) {
        String dayCode = "WED";
        
        // Modern Switch Expression returning a assigned value
        String dayType = switch (dayCode) {
            case "MON", "TUE", "WED", "THU", "FRI" -> "Weekday";
            case "SAT", "SUN" -> "Weekend";
            default -> "Invalid Day";
        };

        System.out.println(dayCode + " is categorized as: " + dayType);

        // Ternary Operator for inline decision making
        int score = 88;
        String status = (score >= 60) ? "PASS" : "FAIL";
        System.out.println("Exam Outcome: " + status);

        // Nested Ternary example (Use with caution for readability)
        String gradeTier = (score >= 90) ? "A" :
                           (score >= 80) ? "B" :
                           (score >= 70) ? "C" : "F";
        System.out.println("Grade Tier: " + gradeTier);
    }
}

Module 3: While & Do-While

Conceptual Explanation & Architectural Mechanics

When the exact number of iteration cycles is unknown prior to loop entry, event-driven loop constructs are required. Java provides while and do-while loops for non-deterministic iterations, relying on dynamic condition evaluation.

The fundamental structural differences are centered around condition evaluation order:

  • while (condition): Pre-test loop. The boolean condition is evaluated before executing the loop body. If the condition is false initially, the body executes zero times.
  • do { ... } while (condition);: Post-test loop. The loop body executes unconditionally first, and the condition is evaluated at the bottom. The body is guaranteed to execute at least once.

Loop execution flow can be controlled dynamically using break and continue statements. break immediately terminates the enclosing loop, transferring control to the next instruction outside the loop block. continue skips the remainder of the current iteration body and jumps directly to the condition re-evaluation step.

Infinite Loop Sentinel Trap:
When using while loops for reading interactive input until a sentinel value (e.g., -1), ensure your update or scan statement is updated inside the loop body to avoid creating an infinite execution loop.

Student Hands-on Code

import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        // While Loop Example: Computing Greatest Common Divisor (Euclidean Algorithm)
        int a = 56, b = 98;
        int origA = a, origB = b;

        while (b != 0) {
            int temp = b;
            b = a % b;
            a = temp;
        }
        System.out.println("GCD of " + origA + " and " + origB + " is: " + a);

        // Do-While Loop Example: Interactive Input Validation
        Scanner scanner = new Scanner(System.in);
        int inputVal;

        do {
            System.out.print("Enter a positive number (>0): ");
            inputVal = scanner.nextInt();
        } while (inputVal <= 0);

        System.out.println("Valid Input Received: " + inputVal);
        scanner.close();
    }
}

Module 4: For & Enhanced For

Conceptual Explanation & Architectural Mechanics

For deterministic loop iterations where loop bounds or iteration counts are known beforehand, the for loop family offers structured and highly readable control logic. Java supports standard index-based for loops as well as the Enhanced For loop (also known as the For-Each loop).

The standard for loop consists of three structural statements inside its control block:

for (initialization; terminationCondition; updateStep) {
    // Loop body
}

Execution order follows a strict sequence: Initializer executes once \(\rightarrow\) Termination Condition is evaluated \(\rightarrow\) If true, Body executes \(\rightarrow\) Update Step executes \(\rightarrow\) Condition re-evaluated.

The Enhanced For Loop (introduced in Java 5) simplifies traversal over arrays and collections implementing Iterable:

for (ElementType element : collectionOrArray) {
    // Operations on element
}

Under the hood, for arrays, the Java compiler transforms an enhanced for loop into an optimized indexed access loop. For Collections, it compiles into an implicit Iterator traversal. However, enhanced for loops are read-only regarding array references; you cannot modify structural indices or replace array elements directly through the loop iteration variable.

Enhanced For Limitation:
Never use an enhanced for loop if you need to access the element's index, step through elements at custom intervals (e.g., i += 2), or modify array values directly.

Student Hands-on Code

public class Main {
    public static void main(String[] args) {
        int[] dataset = {12, 45, 67, 23, 89, 34};

        // Standard Index-based For Loop
        System.out.print("Indexed Forward Scan: ");
        for (int i = 0; i < dataset.length; i++) {
            System.out.print(dataset[i] + " ");
        }
        System.out.println();

        // Reverse Traversal via Standard For Loop
        System.out.print("Reverse Array Scan:   ");
        for (int i = dataset.length - 1; i >= 0; i--) {
            System.out.print(dataset[i] + " ");
        }
        System.out.println();

        // Enhanced For-Each Loop
        int totalSum = 0;
        for (int value : dataset) {
            totalSum += value;
        }
        System.out.println("Total Sum via Enhanced For: " + totalSum);
    }
}

Module 5: Dynamic Arrays (ArrayList)

Conceptual Explanation & Architectural Mechanics

While primitive fixed arrays (int[]) require declaring memory capacity upfront, real-world applications and algorithms often handle variable-length data streams. The ArrayList class, defined in java.util, is a resizable dynamic array implementation of the List interface.

An ArrayList manages an internal standard array reference. When elements are added, the class automatically manages backing storage resize operations:

  • Initial Capacity: Defaults to 10 element slots upon creation unless specified.
  • Growth Factor: When adding an element exceeds current capacity, a new internal array is allocated with approximately 1.5x the previous capacity (\(\text{newCapacity} = \text{oldCapacity} + (\text{oldCapacity} \gg 1)\)).
  • Array Copying: Existing elements are copied to the new array using System.arraycopy(), resulting in an amortized constant time \(\mathcal{O}(1)\) for append operations.

Generics (ArrayList<T>) enforce compile-time type safety. Because generics work only with reference types, primitive types must be wrapped using their corresponding Object Wrapper classes (e.g., Integer for int, Double for double). Java automatically converts between primitives and wrappers via Autoboxing and Unboxing.

Time Complexity Awareness:
Adding/getting at the end of an ArrayList is \(\mathcal{O}(1)\) amortized. However, inserting or removing elements at arbitrary middle positions requires element shifting, making it an \(\mathcal{O}(N)\) operation.

Module 6: HashSet & Unique Sets

Conceptual Explanation & Architectural Mechanics

When algorithmic requirements call for maintaining unique element collections or testing membership rapidly, sequential list searching (\(\mathcal{O}(N)\)) creates severe performance bottlenecks. The HashSet class in java.util implements the Set interface, offering constant time \(\mathcal{O}(1)\) average performance for lookup, insertion, and deletion operations.

A HashSet is backed internally by a HashMap instance. Elements added to a HashSet are stored as keys inside the underlying hash table. Uniqueness and lookup mechanics rely on two key methods defined in java.lang.Object:

  • hashCode(): Computes an integer hash value for an object, determining its primary bucket position in the hash table array.
  • equals(Object obj): Resolves collisions if multiple objects hash to the exact same bucket bucket index.

Properties of HashSet:

  • No Duplicates: Adding an element already present in the set leaves the set unchanged and returns false.
  • Unordered: Does not preserve element insertion sequence. Iterating over a HashSet yields arbitrary ordering.
  • Null Support: Allows at most one null element.
Preserving Insertion Order:
If set uniqueness is required alongside predictable insertion order, use LinkedHashSet. For automatically sorted sets, use TreeSet (\(\mathcal{O}(\log N)\) performance backed by a Red-Black tree).

Module 1: Classes & Objects

Conceptual Explanation & Architectural Mechanics

Object-Oriented Programming (OOP) forms the core architectural paradigm of Java. A Class serves as a blueprint or template defining the state (fields/attributes) and behavior (methods) of a real-world entity or abstract concept. An Object is a concrete runtime instance allocated in heap memory created from that class blueprint.

Key Encapsulation Principles and Access Control Modifiers:

  • private: Restricts access exclusively to methods within the declaring class. Fields should almost always be private to enforce data hiding and encapsulation.
  • public: Allows unrestricted access from any package or class.
  • protected: Grants access within the same package and sub-classes in external packages.
  • Package-Private (Default): Grants access strictly within the declaring package when no modifier is provided.

Constructors are special method-like blocks invoked automatically during object instantiation via the new operator. They share the exact name of the class and have no explicit return type. The this keyword resolves reference ambiguity by referring directly to the instance on which the constructor or method is executing (e.g., this.name = name;).

Custom Sorting via Comparable:
To sort custom objects using Collections.sort() or Arrays.sort(), implement the Comparable<T> interface and override its compareTo(T o) method. Return negative if this object precedes o, positive if it succeeds o, or 0 if equal.

Module 2: HashMap (Key-Value)

Conceptual Explanation & Architectural Mechanics

In competitive programming and software systems, mapping unique keys to corresponding values is a fundamental requirement. The HashMap<K, V> class in java.util implements the Map interface, providing average constant time \(\mathcal{O}(1)\) performance for key-based search, insertion, and removal operations.

Underneath the surface, a HashMap maintains an array of hash buckets (node arrays). Insertion steps execute as follows:

  1. The key's hashCode() is evaluated to determine the target bucket array index.
  2. If no key exists at that bucket index, a new node storing the key-value pair is inserted.
  3. If a collision occurs (multiple keys sharing the same bucket index), nodes are chained using a Linked List. In Java 8+, if chain length exceeds 8 items, the bucket structure automatically transforms into a Red-Black Tree to guarantee worst-case \(\mathcal{O}(\log N)\) performance.

Essential HashMap methods:

  • .put(K key, V value): Associates key with value. Overwrites existing value if key is present.
  • .get(Object key): Retrieves mapped value, or null if key doesn't exist.
  • .getOrDefault(Object key, V defaultValue): Returns mapped value, or specified default value if key absent (extremely useful for frequency counting!).
  • .containsKey(Object key): Returns boolean indicating key existence.
  • .keySet() / .entrySet(): Returns Set views of keys or Key-Value entry pairs for iteration.
Frequency Counting Pattern:
Instead of checking containsKey() before updating counts, use map.put(key, map.getOrDefault(key, 0) + 1); to increment key frequencies in a single concise line.

Student Hands-on Code

import java.util.HashMap;
import java.util.Map;

public class Main {
    public static void main(String[] args) {
        String[] votes = {"Alice", "Bob", "Alice", "Charlie", "Alice", "Bob"};
        HashMap tallyMap = new HashMap<>();

        // Counting element frequencies using getOrDefault
        for (String candidate : votes) {
            tallyMap.put(candidate, tallyMap.getOrDefault(candidate, 0) + 1);
        }

        System.out.println("Complete Tally Map: " + tallyMap);

        // Iterating over Entry Set
        String winner = "";
        int maxVotes = -1;

        for (Map.Entry entry : tallyMap.entrySet()) {
            System.out.println(entry.getKey() + " received " + entry.getValue() + " votes.");
            if (entry.getValue() > maxVotes) {
                maxVotes = entry.getValue();
                winner = entry.getKey();
            }
        }

        System.out.println("Election Winner: " + winner + " with " + maxVotes + " votes.");
    }
}

Module 3: 2D Arrays & Grids

Conceptual Explanation & Architectural Mechanics

Two-dimensional grids model spatial boards, mazes, matrices, and images in competitive programming. In Java, a 2D array (int[][] grid) is structured as an array of array references. Dimensions are indexed as grid[row][col] where row ranges from 0 to grid.length - 1 and col ranges from 0 to grid[row].length - 1.

Grid Navigation and Direction Vectors:

Moving across adjacent grid cells (Up, Down, Left, Right) requires evaluating row and column offsets. Instead of writing four repetitive if statements, algorithmic programmers define parallel Direction Offsets arrays:

// Up, Down, Left, Right direction vectors
int[] dRow = {-1, 1, 0, 0};
int[] dCol = { 0, 0,-1, 1};

Boundary Validation Function:

Before accessing grid[r + dRow[i]][c + dCol[i]], you must validate that candidate coordinates fall within matrix boundaries to prevent throwing an ArrayIndexOutOfBoundsException:

public static boolean isValid(int r, int c, int rows, int cols) {
    return r >= 0 && r < rows && c >= 0 && c < cols;
}
Grid Scanning Order:
Always iterate outer loops by row and inner loops by column (row-major order). This aligns with Java's internal memory layout, providing spatial cache locality for optimal CPU performance.

Module 4: Fast I/O (BufferedReader)

Conceptual Explanation & Architectural Mechanics

In competitive programming platforms like DMOJ, USACO, and Codeforces, problem test cases contain datasets up to \(10^6\) lines. Standard java.util.Scanner parses inputs using complex regular expressions internally, creating significant performance overhead that causes time-limit exceeded (TLE) verdicts.

High-performance Java I/O architecture replaces Scanner and standard System.out.println with BufferedReader, StringTokenizer, and PrintWriter:

  • BufferedReader: Reads characters from an input stream using an internal 8KB memory buffer, drastically reducing direct system call context switches.
  • StringTokenizer: Splices input lines into raw string tokens separated by whitespace at maximum speed.
  • PrintWriter: Buffers text output in memory before flushing to stdout in large blocks, bypassing System.out.println's automatic thread locks and flushing overhead.
Crucial PrintWriter Rule:
When using PrintWriter, you must call out.flush() or out.close() at the end of the program. If you forget to flush the buffer, output text remains trapped in memory and online judges will evaluate your submission as printing empty output!

Student Hands-on Code

import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.io.PrintWriter;
import java.io.BufferedOutputStream;
import java.io.IOException;
import java.util.StringTokenizer;

public class Main {
    public static void main(String[] args) throws IOException {
        // Fast I/O Initialization Boilerplate
        BufferedReader reader = new BufferedReader(new InputStreamReader(System.in));
        PrintWriter out = new PrintWriter(new BufferedOutputStream(System.out));
        StringTokenizer tokenizer = null;

        // Reading line 1 containing N integers count
        String line1 = reader.readLine();
        if (line1 != null) {
            tokenizer = new StringTokenizer(line1);
        }

        if (tokenizer != null && tokenizer.hasMoreTokens()) {
            int n = Integer.parseInt(tokenizer.nextToken());
            out.println("Processing " + n + " elements fast...");
            
            // Reading second line containing N space-separated numbers
            String line2 = reader.readLine();
            if (line2 != null) {
                tokenizer = new StringTokenizer(line2);
                long sum = 0;
                while (tokenizer.hasMoreTokens()) {
                    sum += Integer.parseInt(tokenizer.nextToken());
                }
                out.println("Sum Result: " + sum);
            }
        }

        // ALWAYS flush output buffer!
        out.flush();
        out.close();
    }
}

Module 5: Prefix Sum Arrays

Conceptual Explanation & Architectural Mechanics

Range sum queries are a common algorithmic challenge. Given an array of numbers, calculate the sum of elements between 1-based indices \(L\) and \(R\) across \(Q\) independent queries. A naive loop computes each query in \(\mathcal{O}(N)\) time, yielding total time complexity of \(\mathcal{O}(Q \times N)\)—which fails when \(N, Q \le 10^5\).

The Prefix Sum Array technique optimizes range sum queries down to constant time \(\mathcal{O}(1)\) per query after an \(\mathcal{O}(N)\) pre-processing step!

Mathematical Construction:

Construct a 1-indexed prefix array P of size \(N + 1\), where P[i] stores the cumulative sum of elements from index 0 up to i - 1:

\[ P[i] = P[i - 1] + \text{arr}[i - 1] \]

To evaluate any range query sum between 1-indexed boundaries \(L\) and \(R\), apply the fundamental range identity formula:

\[ \text{Sum}(L, R) = P[R] - P[L - 1] \]
1-Based Padding Advantage:
Using a 1-indexed Prefix array of size \(N + 1\) with P[0] = 0 eliminates boundary check conditions (e.g., handling \(L = 0\)), cleanly preventing index out of bounds exceptions.

Student Hands-on Code

public class Main {
    public static void main(String[] args) {
        int[] arr = {3, 7, 2, 5, 8, 4}; // Indices 0..5
        int n = arr.length;

        // Build 1-indexed Prefix Sum Array of size N + 1
        long[] pref = new long[n + 1];
        pref[0] = 0; // Base case

        for (int i = 1; i <= n; i++) {
            pref[i] = pref[i - 1] + arr[i - 1];
        }

        // Query 1: Sum from index 1 to 4 (values: 7, 2, 5, 8) -> 1-indexed L=2, R=5
        int L = 2, R = 5;
        long rangeSum = pref[R] - pref[L - 1];
        System.out.println("Sum from index " + L + " to " + R + ": " + rangeSum);

        // Query 2: Entire array sum -> L=1, R=6
        System.out.println("Total array sum: " + (pref[n] - pref[0]));
    }
}

Module 6: Stack, Queue & PQ

Conceptual Explanation & Architectural Mechanics

Linear and prioritized abstract data structures manage ordering and processing workflows in advanced graph and greedy algorithms.

Core Data Structures & Java Implementations:

  • Stack (LIFO - Last In, First Out): Operations occur at the top pointer. push(e), pop(), and peek() run in \(\mathcal{O}(1)\). In modern Java, use ArrayDeque<T> instead of the legacy java.util.Stack class.
  • Queue (FIFO - First In, First Out): Elements enter at the tail (offer(e)) and exit from the head (poll()). Implemented via ArrayDeque<T> or LinkedList<T> acting on the Queue interface.
  • PriorityQueue (PQ): Elements are dequeued based on priority order rather than insertion sequence. Backed by a Binary Heap structure, insertion (add()) and removal (poll()) execute in \(\mathcal{O}(\log N)\) time, while inspecting the top priority element (peek()) executes in \(\mathcal{O}(1)\). Defaults to a Min-Heap.
Custom PriorityQueue Comparator:
To configure a PriorityQueue as a Max-Heap (largest values dequeued first), pass Collections.reverseOrder() into its constructor: PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder());.

Student Hands-on Code

import java.util.ArrayDeque;
import java.util.PriorityQueue;
import java.util.Collections;

public class Main {
    public static void main(String[] args) {
        // Stack usage for bracket matching / LIFO ops
        ArrayDeque stack = new ArrayDeque<>();
        stack.push("Page 1");
        stack.push("Page 2");
        stack.push("Page 3");

        System.out.println("Stack Top (Peek): " + stack.peek());
        System.out.println("Stack Pop: " + stack.pop()); // Removes Page 3

        // Queue usage for FIFO ops
        ArrayDeque queue = new ArrayDeque<>();
        queue.offer("Customer A");
        queue.offer("Customer B");
        System.out.println("Queue Service Order: " + queue.poll()); // Serves Customer A

        // PriorityQueue (Max-Heap setup)
        PriorityQueue maxHeap = new PriorityQueue<>(Collections.reverseOrder());
        maxHeap.add(45);
        maxHeap.add(99);
        maxHeap.add(12);

        System.out.println("Highest Priority Extracted: " + maxHeap.poll()); // 99
    }
}

Module 7: Graph Traversal (BFS)

Conceptual Explanation & Architectural Mechanics

Breadth-First Search (BFS) is a fundamental graph traversal algorithm that explores nodes level-by-level in order of their distance from the source. In unweighted graphs or grids, BFS guarantees finding the **shortest path** from a starting node to all reachable target nodes.

BFS Mechanics & Queue Architecture:

  1. Initialize a FIFO Queue to store active boundary nodes, and a 2D boolean[][] visited grid to prevent processing the same cell multiple times.
  2. Enqueue the starting coordinates (startR, startC), mark as visited, and set starting distance to 0.
  3. While the queue is not empty:
    • Dequeue the current node coordinate.
    • Explore all valid adjacent neighbors using direction vectors (Up, Down, Left, Right).
    • For each valid, unvisited neighbor cell, mark it as visited, record its distance as currentDist + 1, and enqueue it.
BFS Shortest Path Guarantee:
Because BFS visits nodes level-by-level, the first time the destination cell is dequeued, the recorded step count is mathematically guaranteed to be the shortest path in unweighted graphs.

Student Hands-on Code

import java.util.ArrayDeque;

public class Main {
    static class Node {
        int r, c, dist;
        Node(int r, int c, int dist) {
            this.r = r;
            this.c = c;
            this.dist = dist;
        }
    }

    public static void main(String[] args) {
        int[][] grid = {
            {1, 1, 0},
            {0, 1, 1},
            {0, 0, 1}
        };

        int rows = grid.length, cols = grid[0].length;
        boolean[][] visited = new boolean[rows][cols];
        ArrayDeque queue = new ArrayDeque<>();

        // Start BFS from Top-Left (0, 0)
        queue.offer(new Node(0, 0, 0));
        visited[0][0] = true;

        int[] dRow = {-1, 1, 0, 0};
        int[] dCol = { 0, 0,-1, 1};
        int shortestPath = -1;

        while (!queue.isEmpty()) {
            Node curr = queue.poll();

            // Check if bottom-right target reached
            if (curr.r == rows - 1 && curr.c == cols - 1) {
                shortestPath = curr.dist;
                break;
            }

            for (int i = 0; i < 4; i++) {
                int nr = curr.r + dRow[i];
                int nc = curr.c + dCol[i];

                if (nr >= 0 && nr < rows && nc >= 0 && nc < cols && grid[nr][nc] == 1 && !visited[nr][nc]) {
                    visited[nr][nc] = true;
                    queue.offer(new Node(nr, nc, curr.dist + 1));
                }
            }
        }

        System.out.println("Shortest Grid Path Distance: " + shortestPath);
    }
}

Module 8: Recursion & DFS

Conceptual Explanation & Architectural Mechanics

Recursion is a programming technique where a method calls itself to solve smaller sub-instances of a problem. Depth-First Search (DFS) uses recursion or a Stack to explore graph branches as deeply as possible before backtracking.

Structural Requirements of Recursive Methods:

  • Base Case: A mandatory conditional exit block that stops recursive calls when a simple trivial state is reached. Missing a base case causes an infinite loop resulting in a StackOverflowError.
  • Recursive Step: The logic that breaks the problem into a smaller sub-instance and invokes the method recursively, bringing execution closer to the base case.

DFS Traversals and Backtracking:

DFS explores graph/grid nodes by traversing deep down a path until a dead end or visited state is reached. When reaching a dead end, execution backtracks to previous stack frames to evaluate unvisited branch options. This makes DFS ideal for connectivity analysis (e.g., connected components or island counting algorithms).

Call Stack Overhead:
Every recursive call adds a stack frame to memory. Recursion depths exceeding \(10^4\) frames in competitive programming can trigger StackOverflowError. For deep traversals, consider an iterative approach or adjust thread stack limits.

public class Main {

    // Mathematical Recursion Example: Factorial
    public static long factorial(int n) {
        if (n <= 1) return 1; // Base Case
        return n * factorial(n - 1); // Recursive Step
    }

    // DFS Grid Island Explorer Method
    public static void dfsExplore(int[][] grid, boolean[][] visited, int r, int c) {
        int rows = grid.length, cols = grid[0].length;

        // Base cases for boundary, visited, or wall checks
        if (r < 0 || r >= rows || c < 0 || c >= cols || grid[r][c] == 0 || visited[r][c]) {
            return;
        }

        visited[r][c] = true; // Mark visited

        // Recursive exploration in 4 directions
        dfsExplore(grid, visited, r - 1, c); // Up
        dfsExplore(grid, visited, r + 1, c); // Down
        dfsExplore(grid, visited, r, c - 1); // Left
        dfsExplore(grid, visited, r, c + 1); // Right
    }

    public static void main(String[] args) {
        System.out.println("Factorial (5!): " + factorial(5));

        int[][] map = {
            {1, 1, 0, 0},
            {1, 0, 0, 1},
            {0, 0, 1, 1}
        };

        boolean[][] visited = new boolean[3][4];
        int islandCount = 0;

        for (int i = 0; i < 3; i++) {
            for (int j = 0; j < 4; j++) {
                if (map[i][j] == 1 && !visited[i][j]) {
                    islandCount++;
                    dfsExplore(map, visited, i, j); // Flood fill island
                }
            }
        }

        System.out.println("Total Connected Land Islands: " + islandCount);
    }
}

Problem Demonstration: CCC '21 J3 - Secret Instructions
Decodes 5-digit instruction strings into direction and step count. The first two digits determine direction: sum is odd \(\rightarrow\) left, sum is even non-zero \(\rightarrow\) right, sum is zero \(\rightarrow\) same direction as previous instruction. Remaining 3 digits represent distance steps. Terminated by input 99999.

import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.io.PrintWriter;
import java.io.BufferedOutputStream;
import java.io.IOException;

public class Main {
    public static void main(String[] args) throws IOException {
        BufferedReader reader = new BufferedReader(new InputStreamReader(System.in));
        PrintWriter out = new PrintWriter(new BufferedOutputStream(System.out));

        String line;
        String lastDirection = "";

        while ((line = reader.readLine()) != null) {
            if (line.equals("99999")) break;

            int d1 = line.charAt(0) - '0';
            int d2 = line.charAt(1) - '0';
            String steps = line.substring(2);

            int sum = d1 + d2;
            String currentDirection;

            if (sum == 0) {
                currentDirection = lastDirection;
            } else if (sum % 2 != 0) {
                currentDirection = "left";
            } else {
                currentDirection = "right";
            }

            lastDirection = currentDirection;
            out.println(currentDirection + " " + steps);
        }

        out.flush();
        out.close();
    }
}
