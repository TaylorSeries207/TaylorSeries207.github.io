Lesson 01 / Level 1

Main Method & Output

Before you start: Start here

1. From source code to a running program

Java source is saved in a .java file. A JDK supplies javac, which compiles source into bytecode, and java, which runs that bytecode on a Java Virtual Machine. For these lessons, save one example at a time as Main.java, run javac Main.java, then java Main. Java is statically typed: the compiler checks the types used by your code before it runs.

2. Read the program structure

public class Main declares a class named Main. In this traditional program structure, public static void main(String[] args) is the entry method: public makes it accessible, static lets it run without creating a Main object, void means it returns no value, and args holds command-line arguments. Braces group statements; a semicolon ends most simple statements. Java is case-sensitive.

3. Choose a printing method

System.out.print writes text without adding a line break. println adds a line break after the value. printf uses a format string: %d is an integer, %.2f is a decimal rounded to two places, and %n is a platform line separator. Quoted text is a String literal; it is not the name of a variable.

4. Escape characters and comments

Inside a string, \n creates a newline, \t creates a tab, \" prints a quotation mark, and \\ prints a backslash. A tab moves to a tab stop; it is not a fixed number of spaces. // starts a single-line comment; /* ... */ encloses a block comment. Comments help people and are not printed.

        System.out.println("Java!");
        System.out.println("A\nB");
        System.out.printf(java.util.Locale.US, "Price: %.2f%n", 3.5);
    }

Lesson 02 / Level 1

Variables, Primitive Types & Math

Before you start: Main Method & Output

1. Declare, assign, update

int score = 10 declares a variable, gives it type int, and initializes it. score = 15 changes its value; score += 2 adds two to the existing value. A local variable must be assigned before it is read. final int DAYS = 7 declares a value that cannot be reassigned. Use meaningful camelCase names such as totalScore.

2. Choose the right type

Java has eight primitive types: byte (8-bit), short (16-bit), int (32-bit), long (64-bit), float (32-bit), double (64-bit), char (a 16-bit UTF-16 code unit), and boolean (true or false; its storage size is not specified by the Java language). int ranges from -2,147,483,648 to 2,147,483,647. long reaches about ±9.22 × 10^18. Decimal literals normally use double; append F for float and L for a large long literal.

3. Arithmetic and conversion

+, -, *, / and % mean addition, subtraction, multiplication, division and remainder. Multiplication, division and remainder happen before addition and subtraction; parentheses override precedence. Integer division truncates toward zero: 10 / 3 is 3 and -10 / 3 is -3. Convert an operand before division, as in (double) total / count, to retain a fraction.

4. Overflow and Math helpers

An expression is evaluated before assignment. long product = a * b can overflow if both operands are int; use 1L * a * b. double approximates many decimal fractions, so do not assume exact decimal equality after calculations. Math.min/max select values, Math.abs finds magnitude (except the minimum signed integer edge case), Math.sqrt finds a square root, and Math.PI supplies pi. Math.pow returns double; x * x is often simpler for an integer square.

        System.out.println((double) a / b);
        int side = 1000000;
        long area = 1L * side * side;

Lesson 03 / Level 1

Strings, Characters & Indexing

Before you start: Variables, Primitive Types & Math

1. A character versus a string

char letter = 'A' uses single quotes and stores one UTF-16 code unit. String word = "Java" uses double quotes and refers to a String object. A String can be empty. For these ASCII exercises, each character occupies one index; some Unicode characters such as emoji occupy two UTF-16 positions.

2. Zero-based indexing

The first index is 0 and the last is text.length() - 1. text.charAt(i) reads one char. substring(start, end) includes start but excludes end, so its length is end - start. substring(start) continues to the end. Reading charAt(length()) fails; substring(length()) is allowed and returns an empty string.

3. Search and transform

indexOf returns the first matching index, or -1 if there is no match. contains checks for a substring; startsWith and endsWith check boundaries. toLowerCase, toUpperCase, trim and replace return results. Strings are immutable: these operations do not change the original String object. Store the returned value if you need it.

4. Compare contents correctly

equals compares String contents; equalsIgnoreCase ignores letter case. == compares whether two references refer to the same object. String interning can make an incorrect == test appear to work on literals, so do not use it for text comparison. "yes".equals(value) is safe even when value is null.

Lesson 04 / Level 1

Comparisons & Boolean Logic

Before you start: Variables and Strings

1. A condition produces true or false

<, <=, >, >=, == and != compare primitive values. = assigns a value; == tests equality. An if condition must be boolean: Java does not treat a nonzero integer as true. Prefer >= for an inclusive lower limit and > for a strict lower limit.

2. Combine conditions

&& means both conditions must be true; || means at least one must be true; ! reverses a boolean. To test a score between 0 and 100 inclusive, write score >= 0 && score <= 100. Java does not allow a chained mathematical comparison such as 0 <= score <= 100.

3. Short-circuit evaluation

For A && B, Java skips B when A is false. For A || B, Java skips B when A is true. This lets you guard a dangerous operation: divisor != 0 && value % divisor == 0 never divides by zero. Check a reference for null before accessing its methods.

4. Truth tables and grouping

AND is true only for true/true. OR is false only for false/false. ! binds more tightly than comparisons, && binds more tightly than ||, and parentheses make intent clearer. De Morgan’s rules say !(A && B) is !A || !B, and !(A || B) is !A && !B.

        System.out.println(divisor != 0 && 20 % divisor == 0);

Lesson 05 / Level 1

Scanner Input & If / Else

Before you start: Strings and Boolean Logic

1. Read tokens or read a line

Create Scanner in = new Scanner(System.in). nextInt, nextLong and nextDouble parse the next token; next reads one whitespace-delimited word. nextLine reads the rest of the current line, which can contain spaces or be empty. Input types and order must match the task specification.

2. Understand the newline issue

After nextInt, the rest of that line remains unread. If you now want the following whole line, call nextLine once to consume the current line remainder, then call it again for the next line. Do not insert this cleanup before every string read: it can discard useful data, especially if a name is intentionally on the same line.

3. Select exactly one branch

An if / else if / else chain runs the first branch whose condition is true, then skips the others. Check high thresholds before lower ones when ranges overlap. Separate if statements are independent and may all run. Use braces even for short branches to avoid accidentally attaching else to the wrong if.

4. Interactive versus judge output

A classroom console app may prompt Enter your score. An online judge expects exactly the specified output, so remove prompts. Read the input once, compute the result, and print only what is requested. Scanner is convenient for learning; large input may require buffered input later.

import java.util.*;

public class Main {
    public static void main(String[] args) throws Exception {
        Scanner in = new Scanner(System.in);

        in.nextLine(); // Consume the rest of the score line.
        String name = in.nextLine();
        if (score >= 90) {
            System.out.println(name + ": A");
        } else if (score >= 60) {
            System.out.println(name + ": Pass");
        } else {
            System.out.println(name + ": Fail");
        }
    }
}

Lesson 06 / Level 1

First Loops: Counting & Accumulating

Before you start: Scanner Input & If / Else

1. Why repeat with a loop?

A loop runs a block repeatedly. A counting loop has a starting value, a continuation condition and an update. for (int i = 0; i < 5; i++) runs with i equal to 0, 1, 2, 3 and 4. The condition is checked before each iteration, so a loop can run zero times.

2. Read the execution order

In a for loop, initialize once, check the condition, run the body, update the counter, and return to the condition. i++ increases i by one. i-- decreases it. A variable declared inside the for initializer is available inside the loop, not after it.

3. Accumulators and counters

An accumulator stores a running result: initialize sum = 0 before the loop and use sum += value inside. A counter records how often something occurs and usually increases only inside an if. Initializing sum inside the loop resets it on every iteration and loses previous work.

4. Trace before you run

Write a table with the loop counter, current value and sum after each iteration. For values 2, 4 and 6, the sum changes 0 → 2 → 6 → 12. Ask how many iterations occur and whether the last intended value is included. This habit prevents many off-by-one mistakes.

        }
    }

Lesson 07 / Level 1

Fixed Arrays & Linear Traversal

Before you start: First Loops

1. Create a fixed-size sequence

int[] scores = new int[5] creates an array with five int elements, each initially 0. int[] primes = {2, 3, 5} creates an initialized array. Arrays are objects and variables hold references to them. Their length is fixed after creation, although individual elements can change.

2. Index and length

Read or write with values[i]. Valid indices run from 0 through values.length - 1. The length field has no parentheses. A negative index or index equal to length causes ArrayIndexOutOfBoundsException. Use i < values.length for traversal.

3. Build a running summary

To compute a sum, visit each element once and add it to an accumulator. To find min or max in a nonempty array, initialize with values[0], then compare the remaining elements. Starting max at 0 gives an incorrect result when every value is negative.

4. References and copying

int[] b = a makes b refer to the same array as a; changing b[0] also changes a[0]. Use a.clone() or Arrays.copyOf(a, a.length) for a separate one-dimensional primitive array. Arrays.toString(a) gives readable contents; printing a directly does not print all elements.

Worked example · Predict, then run

Main.java · Complete runnable example
import java.util.*;

public class Main {
    public static void main(String[] args) throws Exception {
        int[] values = {4, -2, 7, 1};
        int sum = 0;
        for (int i = 0; i < values.length; i++) {
            sum += values[i];
        }
        System.out.println(Arrays.toString(values));
        System.out.println(sum);
        int[] copy = values.clone();
        copy[0] = 99;
        System.out.println(values[0]);
    }
}

Lesson 08 / Level 1

Methods, Return Values & Scope

Before you start: Arrays and Loops

1. Define a reusable operation

A method has a name, return type and parameters. static int square(int n) receives an int and returns an int. Call square(5) to evaluate it. Parameters are local names for the argument values. Methods belong inside the class, outside other methods; Java does not support declaring a normal method inside main.

2. Return versus print

return sends a value back to the caller and ends that method call. println writes output but does not provide a calculated return value. Use a returned result in a larger expression, store it, or print it. A void method performs an action and can use return; to exit early without a value.

3. Scope and static

A local variable exists only within its enclosing block. A field belongs to a class or object. These introductory helper methods are static so static main can call them directly. Later object lessons use instance methods that operate on each object’s fields. Overloading allows the same method name with different parameter lists, not merely different return types.

4. Pass-by-value

Java always copies argument values into parameters. Changing an int parameter does not change the caller’s int. For an array, the copied value is a reference, so writing an element can affect the shared array. Reassigning the parameter to a new array does not replace the caller’s reference.

Worked example · Predict, then run

Main.java · Complete runnable example
import java.util.*;

Debugging, Exceptions & Null

Before you start: Methods and Arrays

1. Three different error types

A compile-time error prevents compilation: examples include a missing semicolon, undefined variable or incompatible type. A runtime exception occurs while running, such as an invalid array index. A logic error produces a result that does not match the task even though the program runs. Each type requires a different investigation.

2. Read the evidence

Start with the first meaningful compiler error; later errors may be consequences. For an exception, read its type and the line in your own code shown by the stack trace. For a wrong answer, trace variables on a tiny input and compare actual output with your hand calculation. Remove diagnostic prints before submitting.

3. What null means

null means a reference does not currently refer to an object. Calling text.length() when text is null throws NullPointerException. Integer.parseInt can throw NumberFormatException when text is not a valid int. finally normally runs after try/catch and is used for cleanup; try-with-resources is often better for files. Do not use a broad catch to silently ignore every programming error.

Random Numbers & Reproducible Tests

Before you start: Loops and Math

1. Generate a bounded integer

Random rng = new Random() creates a pseudorandom generator. rng.nextInt(bound) returns a value from 0 inclusive to bound exclusive. For a six-sided die, use rng.nextInt(6) + 1. The bound must be positive. A pseudorandom sequence is generated by an algorithm, not by true physical randomness.

2. Convert to an inclusive range

For small int limits low <= high, rng.nextInt(high - low + 1) + low generates from low through high inclusive. The +1 includes the upper endpoint. The range width must fit a positive int; this simple expression is not suitable for the entire int range.

3. Seeds make debugging repeatable

new Random(42) begins a deterministic sequence. The same seed and the same order of calls produce the same sequence with java.util.Random. Use a fixed seed while debugging; use the default constructor for varied classroom simulations. Random is not suitable for passwords or security tokens.

4. Test properties instead of guessing output

For random results, check invariants such as 1 <= roll && roll <= 6. A simulation average usually gets closer to its expected value over many trials, but individual outcomes vary. A random test does not prove correctness; also test deliberate boundary cases.

Switch & Ternary Expressions

Before you start: If / Else

1. Use switch for discrete choices

A switch selects among exact values such as menu numbers, characters or strings. It is useful when many branches compare the same expression with different constants. Use if / else for ranges such as score >= 80. A default branch handles values not covered by a case.

2. Traditional switch and break

A traditional case uses a colon. After a matching case, execution continues into following cases unless break or return stops it. This is called fall-through. Intentional fall-through can combine several labels; accidental fall-through can print multiple answers. Our runnable examples use Java 8-compatible syntax.

3. Modern switch expressions

Switch expressions became a standard feature in Java 14. For example, String type = switch (day) { case 6, 7 -> "Weekend"; default -> "Weekday"; }; produces a value and arrow cases do not fall through. A block can use yield to supply its value. Check the compiler version before using this syntax on a judge.

4. The ternary operator

condition ? valueIfTrue : valueIfFalse is an expression that selects one value. String status = score >= 60 ? "PASS" : "FAIL" is a compact assignment. Only the chosen operand is evaluated. Prefer if / else when a branch needs multiple steps or nested ternaries become hard to read.

While, Do-While & Sentinel Input

Before you start: First Loops

1. When the number of repetitions is unknown

while (condition) checks before each iteration and runs only while the condition is true. It fits sentinel input, repeated digit extraction and simulations that stop at a state. Every loop needs a reason it will finish: input eventually reaches a sentinel, a value decreases, or a counter reaches a limit.

2. A sentinel is a stop marker

If -1 ends a sequence, read a value, check whether it is -1, and stop before adding it to the data. The sentinel is usually not part of the answer. while (true) with an explicit break is useful when the stopping condition is known only after reading input.

3. Do-while runs at least once

do { body } while (condition); executes its body before checking. It is useful for processing the number zero as one digit or asking for a menu choice at least once. Remember the semicolon after the final while condition. A normal while loop may execute zero times.

4. Digit extraction and GCD

For a non-negative integer, n % 10 finds the last digit and n /= 10 removes it. Repeating yields digits right to left. Euclid’s GCD algorithm repeatedly changes (a, b) to (b, a % b) until b is zero; the remaining a is the GCD. These are different tasks sharing a shrinking-state loop pattern.

For-Each, Nested Loops & Loop Control

Before you start: Arrays and First Loops

1. Indexed for versus enhanced for

Use an indexed loop when you need the position, neighboring elements or to assign array elements. for (int value : array) reads each element value in sequence without managing an index. Assigning a different int to value changes only the local copy, not the element stored in the array.

2. For-each is not absolute read-only access

If elements are object references, a for-each variable can call a method that changes that object’s fields. Reassigning the loop variable still does not replace the array/list element. Do not structurally add or remove list elements during an enhanced-for traversal unless using a supported iterator operation.

3. Nested loops

An outer loop can choose a row and an inner loop a column. The inner loop runs from its own beginning for each outer iteration. With R rows and C columns, the body runs R*C times. If both limits are N, that is N² work, which can become slow for large inputs.

4. Break and continue

break exits the nearest enclosing loop. continue skips the rest of the current iteration and moves to the loop’s next step. In an ordinary for loop, the update still runs after continue. In a while loop, placing the only update after continue can cause an infinite loop.

StringBuilder & Text Processing

Before you start: Strings and Loops

1. Why repeated string concatenation can be costly

String objects are immutable. Repeatedly appending to an increasingly long String in a loop can create and copy many intermediate results. A StringBuilder stores a mutable sequence, so append can extend it without recreating the whole text each time. A single small concatenation is still perfectly readable.

2. Core operations

Create new StringBuilder(), append text or values, inspect length() or charAt(i), and call toString() when a String is needed. setCharAt changes one position. delete(start, end) removes a range with an exclusive end. reverse reverses the builder’s contents. These operations mutate the builder itself.

3. Inspect characters

For ASCII text, ch >= '0' && ch <= '9' tests a digit, and ch - '0' converts it to an integer. Character.isDigit and Character.isLetter also recognize many Unicode characters. Do not combine a Unicode-wide digit test with an ASCII-only subtraction unless inputs are restricted to ASCII.

4. Split carefully

String.split takes a regular expression, so split(".") does not mean a literal dot. A literal dot requires an escaped regex. For whitespace tokens, trim then split("\\s+") in Java source; an empty line needs separate handling. Scanner.next is often easier while learning token input.

ArrayList & Safe Removal

Before you start: Arrays and Loops

1. A resizable list

An array has a fixed length; an ArrayList can grow and shrink. ArrayList<Integer> stores Integer wrapper objects because Java generic type arguments cannot be primitive int. Autoboxing converts int values to Integer when needed; unboxing converts back. A null Integer cannot be unboxed safely.

2. Read and change elements

add(value) appends. add(index, value) inserts and shifts later elements right. get(index) reads, set(index, value) replaces, size() counts elements, and contains(value) checks membership. Existing-element indices must be less than size; insertion also permits index equal to size.

3. Two meanings of remove

For ArrayList<Integer>, remove(1) removes the element at index 1. remove(Integer.valueOf(1)) removes the first element whose value is 1. This overload is a common source of bugs. Deletion shifts following elements left, so forward deletion can skip an element.

4. Performance and safe traversal

get and set are O(1). Appending is amortized O(1), while insertion or removal near the front is O(N) due to shifting. Remove by looping backward, using an Iterator’s remove, or using removeIf. Do not call list.remove inside an enhanced-for loop over the same list.

HashSet, Uniqueness & Membership

Before you start: ArrayList

1. A set stores distinct values

HashSet contains at most one equal value. add returns true when a new value is inserted and false when it was already present. contains checks membership, remove deletes a value, and size returns the number of distinct values. A set does not store how many times each value appeared.

2. Ordering is not guaranteed

HashSet iteration order is unspecified and should not be used for exact-output tasks. If the result must be sorted, copy into a list and sort it or use a TreeSet. LinkedHashSet preserves insertion order. Choose the data structure based on the required output order.

3. Expected performance

HashSet typically provides expected O(1) add, remove and contains with suitable hashing. This is not an unconditional worst-case guarantee. The equals and hashCode methods determine whether objects are treated as equal; built-in Integer and String already provide suitable implementations.

Use seen for values encountered at least once. If seen.add(x) returns false, x has appeared before, so add it to duplicates. duplicates ensures a value appearing three or more times is still reported only once. Sort the final duplicate values when deterministic output is required.

Sorting, Linear Search & Comparators

Before you start: Arrays and ArrayList

1. Sort built-in containers

Arrays.sort(a) sorts a primitive array ascending. Collections.sort(list) sorts a list in natural order. Both modify the given container; copy first if the original order is needed. Numeric order and lexicographic String order are different: "10" comes before "2" as text.

2. Search without assumptions

A linear search inspects positions from left to right and can return the first matching index or -1. It works on unsorted input in O(N). Sorting first changes original indices, so do not sort if the answer requires original positions unless you preserve them separately.

3. Control the order

For an Integer[] or an object list, provide a Comparator. Integer.compare(a, b) orders ascending; reversing arguments orders descending. Comparing by a - b can overflow. Primitive int[] cannot directly use a Comparator; sort ascending and traverse backward when you only need descending output.

4. Tie-breaking

If two students have equal scores, decide the next criterion, such as name ascending. A comparator must be consistent: compare score first, then name only when scores tie. Sorting is useful for ranking, grouping equal values and preparing binary search, but it has an extra cost compared with a single scan.

Classes, Objects & Encapsulation

Before you start: Methods and Scope

1. A class is a definition; an object is an instance

A class groups fields (stored state) and methods (behavior). Student can define name and score; new Student("Mia", 85) creates one object with its own values. Another Student object can have different values. A reference variable points to an object; assigning one reference to another does not clone the object.

2. Constructors and this

A constructor has the class name and no return type. It initializes a newly created object. In this.name = name, this.name means the field of the current object and name means the parameter. A constructor can check invariants, such as a score being between 0 and 100, before storing data.

3. Private fields and public methods

Encapsulation hides fields behind methods so callers cannot freely put an object into an invalid state. private restricts access to the declaring class; public exposes an operation. A getter returns a value. An update method can validate a new value instead of allowing uncontrolled assignment.

4. Instance, static and ordering

An instance method uses a particular object’s fields. A static method belongs to the class and has no this. Implementing Comparable<Student> supplies a natural order through compareTo. Return a negative result for before, zero for tied order, and positive for after; use Integer.compare to avoid overflow, and add a clear tie-breaker.

Inheritance, Interfaces & Polymorphism

Before you start: Classes and Objects

1. An is-a relationship

Inheritance uses extends to build a subclass from a superclass. A Dog is an Animal, so Dog can specialize behavior inherited from Animal. A class extends at most one class. Use composition for has-a relationships: a Classroom has a list of Students rather than extending Student.

2. Override versus overload

Overriding supplies a subclass implementation of an inherited instance method with a matching signature. @Override asks the compiler to check that you really overrode something. Overloading defines methods with the same name but different parameter lists; it does not replace inherited behavior merely by using the same name.

3. An interface defines a contract

An interface specifies operations that implementing classes provide. A class uses implements and can implement multiple interfaces. For example, different Shape classes can all implement area() even though their calculations differ. Interface methods such as area are public; implementations must not reduce that visibility.

4. Dynamic dispatch

A Shape reference can point to a Circle or Rectangle object. Calling area() selects the actual object’s overridden implementation at runtime. An abstract class can share fields and implementation but cannot be instantiated directly. Interfaces and abstract classes help organize varying behavior without long type-checking if chains.

HashMap & Frequency Tables

Before you start: HashSet and Loops

1. Map a unique key to a value

HashMap<K, V> associates each key with one value. put(key, value) inserts or replaces the value; get(key) retrieves it or returns null when absent. containsKey distinguishes absence from a present key mapped to null. This course uses non-null values to keep frequency tables straightforward.

2. Count with getOrDefault

For each word, getOrDefault(word, 0) obtains the previous count or zero, then put stores that count plus one. A set only tells you whether a word exists; a frequency map tells you how often it appears. Expected add/get cost is O(1) with suitable hashing.

3. Iterate and order results

keySet exposes keys, values exposes values, and entrySet exposes key-value pairs. HashMap does not guarantee iteration order. To print alphabetically, copy keys to a list and sort them; TreeMap is an alternative when sorted keys are continuously needed.

4. Store information for future matches

Two Sum asks for two distinct indices with values summing to target. When visiting x, look for target - x among previously seen values. Check before inserting x so a single element cannot pair with itself. Store values as keys and original indices as values.

2D Arrays, Matrices & Grid Neighbors

Before you start: Arrays and Nested Loops

1. An array of arrays

int[][] grid = new int[rows][cols] creates a rectangular grid of zeros. grid[r][c] selects row r and column c. grid.length counts rows; grid[r].length counts columns in row r. Java also allows jagged arrays whose rows have different lengths, so rectangular assumptions should be explicit.

2. Traverse by rows and columns

An outer loop over rows and an inner loop over columns visits every cell once. For an R-by-C grid this is O(R*C). A row sum fixes r and varies c; a column sum fixes c and varies r. Confusing these roles can produce correct-looking output on square symmetric examples but fail elsewhere.

3. Explore four neighbors

Use dr = {-1, 1, 0, 0} and dc = {0, 0, -1, 1}. Add matching entries to the current row and column to try up, down, left and right. Check 0 <= nr < rows and 0 <= nc < cols before accessing grid[nr][nc]. Diagonal moves require different directions.

4. Diagonals in a square matrix

For a square N-by-N matrix, the main diagonal uses grid[i][i] and the anti-diagonal uses grid[i][N - 1 - i]. Summing both separately counts the center in both when N is odd, which is correct for comparing their sums. A task asking for the union of diagonal cells would need to avoid that double count.

Buffered Input & Output

Before you start: Scanner and Exceptions

1. Why buffering helps

Scanner is convenient but its general token parsing can be slower on very large input. BufferedReader reads chunks of characters, and StringTokenizer splits a line into whitespace tokens. PrintWriter buffers formatted text output. Faster I/O helps overhead; it cannot rescue an algorithm doing billions of unnecessary operations.

2. Read tokens across line boundaries

A reusable next() method checks whether the current tokenizer has any tokens. If not, it reads another line and creates a tokenizer, repeating to skip blank lines. At end-of-file, readLine returns null; handle that deliberately. Do not assume all N values are on one line unless the specification requires it.

3. Convert token text

Integer.parseInt(next()) reads an int; Long.parseLong reads long. These conversions throw when the token is invalid or outside the type’s range. Contest inputs normally satisfy the contract. For missing required input, an EOFException is clearer than repeatedly tokenizing null.

4. Flush the output

PrintWriter may hold data in a buffer. Call flush after the final output or close the writer when appropriate. Build batches with StringBuilder for many short lines, but remember that storing the entire output uses memory. The example flushes once after computing a long sum.

import java.util.*;

    static class FastInput {
        private final BufferedReader reader = new BufferedReader(new InputStreamReader(System.in));

                tokens = new StringTokenizer(line);
            }
            return tokens.nextToken();

File I/O & Resource Management

Before you start: Buffered I/O and Exceptions

1. Console streams versus files

System.in and System.out connect to the console or judge. A file is named persistent data on disk. A relative path such as scores.txt is resolved from the program’s working directory, which is not always the folder containing Main.java in an IDE. Use console I/O for judges unless their instructions explicitly request files.

2. Choose an encoding

A text file stores bytes that must be decoded into characters. Explicit UTF-8 makes behavior consistent across machines. Files.newBufferedReader(path, StandardCharsets.UTF_8) and newBufferedWriter use buffered text access. Files.readAllLines is convenient for small files but loads the whole file into memory.

3. Close resources reliably

A try-with-resources statement declares AutoCloseable resources in parentheses. Java closes them when the block exits, including when an exception occurs. This is safer than hoping a manual close at the end will always execute. Closing a writer also flushes buffered data.

4. Know what writing does

The default newBufferedWriter behavior creates a missing file or truncates an existing one. Do not overwrite valuable files unintentionally. These examples create a uniquely named temporary file, operate on it, and delete it in a finally block. A real project should document its output paths and overwrite policy.

Prefix Sums & Range Queries

Before you start: Arrays and long Arithmetic

1. Store sums of the beginning

Let prefix[i] be the sum of the first i elements of a zero-based array. prefix[0] = 0 and prefix[i + 1] = prefix[i] + a[i]. The prefix array has N + 1 entries. This definition handles a range starting at the first element without a special case.

2. Subtract two prefixes

For a zero-based inclusive range [left, right], the sum is prefix[right + 1] - prefix[left]. The larger prefix includes everything through right; subtracting the smaller removes everything before left. For a one-based inclusive query [L, R], the same stored array gives prefix[R] - prefix[L - 1].

3. Preprocess once, answer many times

Building prefix takes O(N) time and O(N) extra memory. Each range query then takes O(1), giving O(N + Q) for Q queries instead of potentially O(N*Q). Prefix sums are especially useful when the array does not change between queries.

4. Choose limits and numeric types

Even if each a[i] fits int, their sum may exceed int, so long[] is a good default for contest totals. Negative values do not break the formula. A standard prefix array does not support changing an element cheaply because every later prefix would also need adjustment.

Stack, Queue & PriorityQueue

Before you start: Collections

1. Stack: last in, first out

A stack removes the most recently inserted item. ArrayDeque<Integer> supports push, peek and pop for stack use. It fits undo history, nested brackets and iterative DFS. pop fails on an empty deque, so check isEmpty first. Prefer ArrayDeque over the older Stack class for these examples.

2. Queue: first in, first out

A queue removes the oldest inserted item. With ArrayDeque, use offer to append and poll to remove from the front. peek inspects without removing. poll and peek return null when empty. ArrayDeque does not allow null elements, so null can represent absence unambiguously.

3. PriorityQueue: next by priority

PriorityQueue<Integer> is a min-heap by default: poll removes the smallest value. Use Collections.reverseOrder for a max-heap. offer and poll take O(log N); peek takes O(1). Iterating or printing the heap does not yield a fully sorted sequence; repeated polling does.

4. Match the discipline to the task

BFS needs FIFO order, DFS can use LIFO order, and repeatedly selecting the smallest pending value needs a priority queue. For balanced brackets, an opening bracket is pushed and a closing bracket must match the most recent unmatched opening bracket, not the oldest one.

BFS: Shortest Paths in a Grid

Before you start: 2D Arrays and Queues

1. Breadth-first search explores layers

BFS visits the start at distance 0, its neighbors at distance 1, then distance 2, and so on. A FIFO queue preserves this layer order. The first discovery of a cell gives its minimum number of edges from the start when every allowed move has equal cost.

2. Represent distance and visitation

Use dist[r][c] = -1 for undiscovered cells. Set the starting distance to 0, enqueue it, then repeatedly remove a cell and inspect valid open neighbors. When discovering a neighbor, set its distance to current distance + 1 before enqueuing it.

3. Mark when enqueuing

Marking at discovery prevents several frontier cells from adding the same neighbor repeatedly. Each open cell is then enqueued at most once. For an R-by-C grid with four neighbors per cell, time and memory are O(R*C). A general adjacency-list graph takes O(V + E).

4. Know the limits

Ordinary BFS minimizes steps in an unweighted graph, not total cost when edge weights differ. A blocked start or target is unreachable, and a target that remains at -1 after the queue empties is also unreachable. A one-cell open grid has distance 0 because no move is needed.

Worked example · Predict, then run

Main.java · Complete runnable example
import java.util.*;

public class Main {
    static int shortestPath(int[][] grid) {
        int rows = grid.length, cols = grid[0].length;
        if (grid[0][0] == 1 || grid[rows - 1][cols - 1] == 1) return -1;
        int[][] dist = new int[rows][cols];
        for (int[] row : dist) Arrays.fill(row, -1);
        int[] dr = {-1, 1, 0, 0}, dc = {0, 0, -1, 1};
        ArrayDeque<int[]> queue = new ArrayDeque<>();
        dist[0][0] = 0;
        queue.offer(new int[]{0, 0});
        while (!queue.isEmpty()) {
            int[] cell = queue.poll();
            int r = cell[0], c = cell[1];
            for (int d = 0; d < 4; d++) {
                int nr = r + dr[d], nc = c + dc[d];
                if (nr >= 0 && nr < rows && nc >= 0 && nc < cols
                        && grid[nr][nc] == 0 && dist[nr][nc] == -1) {
                    dist[nr][nc] = dist[r][c] + 1;
                    queue.offer(new int[]{nr, nc});
                }
            }
        }
        return dist[rows - 1][cols - 1];
    }

    public static void main(String[] args) throws Exception {
        int[][] grid = {{0, 0, 1}, {1, 0, 0}, {0, 0, 0}};
        System.out.println(shortestPath(grid));

Recursion, DFS & Connected Components

Before you start: Methods, Grids and Stacks

1. A method can call itself

Recursion solves a task through smaller versions of the same task. A base case returns without another recursive call. A recursive step must move toward that base case. factorial(n) = n * factorial(n - 1) with factorial(0) = 1 illustrates the pattern; large n quickly overflows fixed-width integers.

2. The call stack stores unfinished work

In sumTo(3), the call waits for sumTo(2), which waits for sumTo(1), which reaches sumTo(0). Returning then resolves the waiting additions. Each active call consumes stack memory. Deep recursion can throw StackOverflowError in Java; use an explicit stack for large graph traversals.

3. DFS explores deeply before returning

Depth-first search follows a neighbor path before trying alternatives. Track visited vertices so cycles do not recurse forever. An iterative DFS pushes discovered neighbors onto a stack. DFS can find reachability and components, but the first route it finds is not generally the shortest.

4. Count components with an outer scan

Big O & Choosing an Algorithm

Before you start: Loops and Collections

1. Describe growth, not exact seconds

Time complexity describes how the amount of work grows with input size. O(1) is constant work, O(log N) repeatedly shrinks the search space, O(N) scans the data, O(N log N) often appears in efficient sorting, and O(N²) often appears in pairwise comparisons. Actual runtime also depends on constants, Java version and hardware.

2. Count repeated operations

One loop from 0 to N - 1 does N iterations. Two consecutive N-iteration loops do 2N, still O(N). Two nested loops each of length N do N². A loop that doubles its counter visits roughly log2 N values. A triangular loop over j < i does N(N - 1)/2 iterations, which is still O(N²).

3. Use constraints before implementation

For N = 200,000, checking every pair requires about 20 billion comparisons. That is a strong signal to seek sorting, hashing, prefix sums or another efficient strategy. Do not treat a fixed operations-per-second estimate as a universal guarantee; use it only as a rough warning.

4. Memory and proof matter too

An int[N] needs roughly 4N bytes for its elements, plus array overhead. Boxed values and collections use additional memory. State an invariant explaining why the algorithm remains correct as it progresses. Faster incorrect code is still incorrect; compare with a simple brute-force implementation on small inputs when developing a complex method.

Binary Search & Lower Bound

Before you start: Sorting and Big O

1. Exploit a sorted search space

Binary search works when comparisons let you discard part of an ordered space. In an ascending array, if a[mid] is smaller than target, no index at or before mid can be the first value >= target. Discard that half. Repeating halves the candidate interval, giving O(log N) time.

2. Use a half-open interval

For lower bound, keep candidates in [left, right), starting with left = 0 and right = a.length. Compute mid = left + (right - left) / 2. If a[mid] < target, set left = mid + 1; otherwise set right = mid. Stop when left == right.

3. Define the returned position

Lower bound returns the first index with a[index] >= target, or N if no such value exists. To test existence, check index < N && a[index] == target. This convention handles duplicates and insertion positions consistently. Never read a[index] before checking that index is in bounds.

4. Maintain the invariant

Every index before left contains a value < target; every index at or after right contains a value >= target. Each update preserves that claim while shrinking the interval. Arrays.binarySearch also exists, but it does not promise the first occurrence among duplicates; its missing-value result encodes an insertion point.

Two Pointers

Before you start: Arrays, Sorting and Big O

1. Move two positions with a purpose

Two pointers tracks two indices rather than trying all index pairs. The pointers might begin at opposite ends, or one might read while the other writes. The key is proving why advancing a pointer does not discard an answer that still needs consideration.

2. Pair sum in sorted data

In an ascending array, compare a[left] + a[right] with target. If too small, increase left because pairing the same left with a smaller right would be even smaller. If too large, decrease right because pairing the same right with a larger left would be even larger.

3. Why this is linear

Every iteration moves at least one pointer inward. Each pointer moves at most N positions, so the search is O(N) after sorting. If sorting is required first, include its cost and remember it changes original indices. Use long for the pair sum if two ints might overflow.

4. Read/write compaction

For removing duplicates from a sorted array, read visits each element and write tracks the length of the unique prefix. Copy a value only when it differs from the last retained value. The valid result is the first write elements; the unused suffix can contain old values.

Sliding Windows

Before you start: Two Pointers and Running Sums

1. Reuse overlapping work

A sliding window represents a contiguous segment. Adjacent windows share most elements, so recomputing each sum from scratch is wasteful. For a fixed length K, build the first window sum, then add the incoming element and subtract the element leaving the window.

2. Fixed-size maximum sum

For N elements and 1 <= K <= N, compute the first K-element sum, initialize best to that sum, then slide the right edge from K onward. Initializing best to zero is wrong if every possible sum is negative. The algorithm takes O(N) time and O(1) extra space.

3. Variable-size valid windows

For non-negative numbers and a non-negative limit, extend right and add its value. While the sum exceeds the limit, remove values at left and move left forward. Once valid, update the best length. Non-negative values make the sum decrease or stay equal when removing from the left.

4. Know when the rule breaks

With negative values, removing an element can increase the sum, and an invalid window might become valid after later additions. The simple shrink-while-too-large strategy is not generally correct then. A fixed-length window sum still works with negative numbers because it does not use that monotonicity assumption.

Difference Arrays & Range Additions

Before you start: Prefix Sums

1. Store changes instead of every value

A difference array describes how values change between adjacent positions. For offline range additions, begin with zero differences. Adding value to every index in [left, right] can be recorded with only two boundary updates rather than touching the entire interval.

2. Start and stop an effect

Using zero-based inclusive ranges, apply diff[left] += value and diff[right + 1] -= value. The positive event starts the increment and the negative event cancels it after the interval. Allocate N + 1 entries so a range ending at N - 1 can safely write diff[N].

3. Reconstruct with a prefix scan

Accumulate running += diff[i] from left to right. running is the total addition active at position i. For a nonzero initial array, add running to the original a[i]. Use long for differences and reconstructed totals when many updates can accumulate.

4. The offline tradeoff

Q range updates plus one reconstruction take O(N + Q) time. This is ideal when all updates are known before final values are needed. If updates and individual range queries are interleaved, rebuilding after each query loses the benefit; a Fenwick tree or segment tree may be needed in a later course.

Greedy Algorithms & Counterexamples

Before you start: Sorting and Big O

1. Choose locally, but justify globally

A greedy algorithm makes an irreversible choice that looks best now. It is correct only when you can justify that the choice can belong to an optimal overall solution. A convenient rule is not automatically a valid algorithm; search for counterexamples before trusting it.

2. Maximum number of non-overlapping intervals

When every interval counts equally and you want to choose as many as possible, sort by finishing time and choose the next interval whose start is at least the previous chosen end. Choosing the earliest finish leaves the most room for future intervals. These examples use half-open intervals [start, end).

3. Exchange argument

Suppose an optimal schedule begins with a different interval. Replace its first interval with the earliest-finishing one. The replacement ends no later, so all later selected intervals still fit. This produces an equally large schedule containing the greedy choice; repeat the reasoning on the remaining intervals.

4. A common incorrect greedy rule

Taking the largest coin first is not always optimal. With denominations {1, 3, 4}, amount 6 becomes 4 + 1 + 1 under that rule, while 3 + 3 uses fewer coins. Different values or objectives can invalidate a previously correct strategy. Weighted interval scheduling also needs more than the simple interval-count greedy rule.

1D Dynamic Programming

Before you start: Arrays, Methods and Big O

1. Reuse solutions to smaller states

Dynamic programming stores answers to overlapping subproblems so they are not recomputed. Define exactly what dp[i] means before writing a loop. A state might mean the number of ways to reach step i, the minimum cost to reach i, or the best score using the first i items. These meanings lead to different transitions.

2. State, base case, transition, order

For climbing with steps of size 1 or 2, let dp[i] count ways to reach step i. dp[0] = 1 represents one empty way to stay at the start. To reach i, the last move came from i-1 or i-2, so dp[i] is the sum of those states when they exist. Fill i in increasing order so dependencies are ready.

3. Minimum coin count

Let dp[x] be the minimum number of coins to form amount x, or an unreachable sentinel. dp[0] = 0. For each amount, try every positive coin c <= x and improve with dp[x-c] + 1. Under unlimited coin reuse, this explores possible last coins and avoids the incorrect largest-coin-first assumption.

4. Complexity and numeric limits

For amount A and K coin types, the simple coin algorithm uses O(A*K) time and O(A) memory. Counting ways can grow very quickly; use a type that fits the stated limit or a specified modulus. long is not unlimited. Do not use modulo on a minimum-cost value unless the problem explicitly changes that objective.

Lesson 39 / Level 4

2D DP: Grid Paths & LCS

Before you start: 1D Dynamic Programming and Grids

1. Two coordinates describe a state

Some subproblems require two independent positions. For grid paths, dp[r][c] counts ways to reach a cell. For longest common subsequence, dp[i][j] describes two string prefixes. A 2D array is a representation of the state space, not evidence by itself that a task needs dynamic programming.

2. Grid paths with obstacles

For movement only right and down, an open cell receives ways from above and left. A blocked cell has zero ways. Set the open starting cell to 1 and do not overwrite that base case. Fill row by row because each dependency has already been computed. This counts paths; it does not compute a BFS shortest distance.

3. Longest common subsequence

A subsequence preserves order but may skip characters; a substring must be contiguous. Let dp[i][j] be the LCS length of the first i characters of a and first j characters of b. If their final characters match, use dp[i-1][j-1] + 1; otherwise use max(dp[i-1][j], dp[i][j-1]). Empty-prefix states are zero.

4. Time, memory and overflow

LCS takes O(A*B) time and O(A*B) memory in the basic form. Grid DP takes O(R*C). Some versions can keep only a previous row when only the answer value is needed, but begin with the full table for clarity. Path counts can exceed long on large grids; use a stated modulus or BigInteger when required.

Worked example · Predict, then run

Main.java · Complete runnable example
import java.util.*;

public class Main {
    public static void main(String[] args) throws Exception {
        int[][] blocked = {{0, 0, 0}, {0, 1, 0}, {0, 0, 0}};
        int rows = blocked.length, cols = blocked[0].length;
        long[][] dp = new long[rows][cols];
        if (blocked[0][0] == 0) dp[0][0] = 1;
        for (int r = 0; r < rows; r++) {
            for (int c = 0; c < cols; c++) {
                if (blocked[r][c] == 1 || (r == 0 && c == 0)) continue;
                if (r > 0) dp[r][c] += dp[r - 1][c];
                if (c > 0) dp[r][c] += dp[r][c - 1];
            }
        }
        System.out.println(dp[rows - 1][cols - 1]);
    }
}

Follow the execution

  2. The center obstacle remains zero and contributes no paths.
  3. Only the route across the top then down, or down the left then across, reaches the target.
Common mistake / important boundary
Counting all paths in a graph with cycles is different from this acyclic right/down grid recurrence. Specify allowed moves before choosing the DP order.

public class Main {

        String a = "abcde", b = "ace";
        int[][] dp = new int[a.length() + 1][b.length() + 1];
        for (int i = 1; i <= a.length(); i++) {
            for (int j = 1; j <= b.length(); j++) {
                if (a.charAt(i - 1) == b.charAt(j - 1)) dp[i][j] = dp[i - 1][j - 1] + 1;

            }
        }

    }

CCC Case Study: Secret Instructions

Before you start: Strings, Input and Simulation

1. Keep instruction text as text

CCC 2021 J3 supplies five-digit instruction strings ending with sentinel 99999. The first two digits determine a direction, while the remaining three represent steps. Read strings to preserve leading zeros. Convert individual ASCII digit characters with subtraction from '0'.

2. Translate the direction rule

Add the first two digits. An odd sum means left. A positive even sum means right. A zero sum means reuse the previous direction. The zero case must be handled separately from the positive-even case. The original task guarantees that the first instruction does not have a zero sum.

3. Maintain persistent state

Store the previous direction outside the loop so it survives from one instruction to the next. Read a code, stop immediately if it is 99999, update direction only when the digit sum is nonzero, then print direction and step count. The sentinel is not an instruction and must not be processed.

4. Review like a competitor

Test an odd sum, a positive even sum and a zero sum that follows a direction. Check output spaces and leading-zero handling against the task. A solution’s correctness comes from faithfully tracking state, not from using an advanced structure. A Junior 3 case can still make a useful review of an entire pipeline.

Worked example · Predict, then run

Main.java · Complete runnable example
import java.util.*;

public class Main {
    public static void main(String[] args) throws Exception {
        Scanner in = new Scanner(System.in);
        String previous = "";
        while (true) {
            String code = in.next();
            if (code.equals("99999")) break;
            int sum = code.charAt(0) - '0' + code.charAt(1) - '0';
            if (sum % 2 == 1) previous = "left";
            else if (sum != 0) previous = "right";
            int steps = Integer.parseInt(code.substring(2));
            System.out.println(previous + " " + steps);
        }
    }
}
