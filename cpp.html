Lesson 01 / Level 1

Headers, main & Console Output

Before you start: Start here

1. Compile source into a program

Save C++ source in a .cpp file. A compiler checks the code and usually produces a native executable for your platform. These lessons use C++17. Compile with g++ -std=c++17 -Wall -Wextra -pedantic main.cpp -o main, then run ./main on macOS/Linux or .\main.exe in Windows PowerShell when the executable is named main.exe.

2. Read the program structure

#include <iostream> makes the standard stream declarations available. int main() is the entry function for these hosted console programs. Braces group statements; most simple statements end with a semicolon. return 0 reports successful completion to the operating system. C++ is case-sensitive, so Main and main are different names.

3. Namespaces and headers

The standard library places names such as cout and string inside namespace std. using namespace std; lets these short teaching programs omit the std:: prefix. In larger projects and especially headers, prefer explicit std:: names to avoid collisions. Include the standard header for each facility; bits/stdc++.h is a GCC convenience, not a portable standard header.

4. Output, escapes and flushing

cout << value inserts a value into the output stream, and several insertions can be chained. \n creates a newline, \t a tab, \" a quotation mark and \\ a backslash inside a string. endl writes a newline and flushes the stream. Prefer '\n' for routine batch output; deliberate flushing is useful for interactive prompts and judges.

Lesson 02 / Level 1

Variables, Types & Arithmetic

Before you start: Headers and Output

1. Declare and initialize

int score = 10 gives a variable a type and an initial value. score += 5 changes it to 15. const int DAYS = 7 cannot be reassigned. auto count = 3 still has a compile-time type: the compiler deduces int. Automatic local fundamental variables such as int x; are not initialized to zero; initialize them before reading them.

2. Portable sizes versus common machines

On common contest platforms int is 32 bits and long long is 64 bits, but the standard guarantees only minimum ranges: int has at least 16 bits and long long at least 64. double is commonly IEEE 754 binary64 but that exact representation is not universal. bool stores true or false; sizeof(char) is 1 byte, and a byte has at least 8 bits. Use numeric_limits from <limits> when exact type limits matter.

3. Arithmetic, division and precedence

+, -, *, / and % are addition, subtraction, multiplication, division and remainder. For integers, division truncates toward zero: 10/3 is 3 and -10/3 is -3. The remainder operator requires integral operands. Multiplication/division/remainder bind before addition/subtraction; parentheses make an intended order explicit.

4. Promote before calculating

Assigning to long long does not retroactively widen earlier int multiplication. Write 1LL*a*b or cast an operand first. Signed integer overflow is undefined behavior in C++17, not a guaranteed wraparound. static_cast<double>(sum)/count performs floating-point division; converting sum/count afterward has already lost the fraction.

Lesson 03 / Level 1

Decimal Formatting, Math & Money

Before you start: Variables and Arithmetic

1. Control decimal output

Include <iomanip> for fixed and setprecision. fixed << setprecision(2) prints two digits after the decimal point; setprecision(2) without fixed instead controls significant digits. Stream formatting stays active until changed. setw affects the next field, while setfill selects its padding character.

2. Use the math library

<cmath> supplies sqrt, abs overloads, pow, floor, ceil and round. sqrt(x) requires a non-negative real input for a real result. x*x is often clearer than pow(x,2), which works through floating-point arithmetic. If integer differences might overflow, convert before subtracting.

3. Floating-point is approximate

Many decimal fractions, including 0.1, are not exactly representable in a binary floating-point format. Printing two decimals changes the display, not the stored value. For calculated real numbers, use an appropriate tolerance or the judge’s specified comparison rule; no single epsilon is correct for every scale and task.

4. Represent exact cents with integers

For a simple bill with fixed two-decimal prices, storing cents in long long avoids accumulating binary approximation in the subtotal. A tax rule still needs an explicit rounding policy. In this lesson, round positive 13% tax to the nearest cent, with a half-cent rounded up. Real billing systems must follow the required accounting rules.

Lesson 04 / Level 1

string, char & Zero-Based Indexing

Before you start: Variables and Output

1. Characters and strings

char letter = 'A' uses single quotes for one character value. string word = "Hello" uses double quotes for text and requires <string>. std::string is a mutable sequence of char values, unlike Java’s immutable String. With UTF-8 text, size counts bytes rather than user-perceived characters; these indexing exercises use ASCII.

2. Read and write positions

The first character is s[0], and the last character of a nonempty string is s[s.size()-1]. s.size() and s.length() return the same count. For character processing, use indices less than size. s.at(i) checks bounds and can throw out_of_range. Never compute size()-1 for an empty string and then access it.

3. Compare, search and extract

For std::string objects, == compares contents and < compares lexicographically. This differs from comparing raw C-style string pointers. find returns an index or string::npos if no match exists. substr(start, count) uses a character count as its second argument, not an exclusive ending index as in Java.

4. Modify and convert

s[i] = 'X' changes a character. += appends characters or strings; erase removes a range. For ASCII digits, ch-'0' converts a known digit character to its numeric value. The <cctype> functions need an unsigned-char value or EOF; cast to unsigned char before calling them on a possibly negative plain char.

Lesson 05 / Level 1

Comparisons & Boolean Logic

Before you start: Variables and Strings

1. Build a boolean expression

<, <=, >, >=, == and != compare values. = is assignment, not equality; if (x = 5) changes x and then treats 5 as true. Unlike Java, C++ permits numeric values as conditions, with zero false and nonzero true. Still prefer explicit comparisons when they describe your intent more clearly.

2. Combine conditions

&& means both conditions must be true; || means at least one must be true; ! reverses a boolean. To require a score between 0 and 100 inclusive, use score >= 0 && score <= 100. A chained comparison such as 0 <= score <= 100 does not mean the mathematical range test in C++.

3. Use short-circuit evaluation

For A && B, B is skipped when A is false. For A || B, B is skipped when A is true. This protects operations such as divisor != 0 && value % divisor == 0. Put the safety check first; evaluating an invalid division and checking afterward is too late.

4. Trace truth and precedence

AND is true only for true/true, while OR is false only for false/false. && binds more tightly than ||, so use parentheses for mixed logic. De Morgan’s laws turn !(A && B) into !A || !B and !(A || B) into !A && !B. Bitwise & and | are different operators and do not short-circuit.

    int divisor = 0;
    cout << (divisor != 0 && 20 % divisor == 0) << '\n';
    cout << !(age < 12 || !hasTicket) << '\n';

Lesson 06 / Level 1

cin, getline & If / Else

Before you start: Strings and Boolean Logic

1. Read formatted tokens

cin >> x extracts the next value compatible with x’s type, skipping leading whitespace by default. cin >> name reads one word; cin >> a >> b reads two tokens regardless of whether they share a line. For a required token, if (!(cin >> x)) can detect failed extraction rather than continuing with invalid assumptions.

2. Read whole lines deliberately

getline(cin, line) reads through a newline and stores the preceding text, including spaces. After formatted extraction, the current line’s remainder is still unread. If the next input is on the following line, use cin.ignore(numeric_limits<streamsize>::max(), '\n') first. A plain cin.ignore() discards only one character and may not remove trailing spaces.

3. Alternative whitespace handling

getline(cin >> ws, line) skips all leading whitespace before reading a line. This is convenient when leading spaces and empty lines should be ignored, but wrong if those are meaningful input. Choose based on the input contract; do not apply a cleanup call mechanically before every string.

4. Choose branches in the right order

An if / else if / else chain runs the first matching branch and skips the rest. Check higher score thresholds first when ranges overlap. Independent if statements may all execute, which is useful when several labels can apply. Remove classroom prompts from online-judge submissions unless requested by the output specification.

Lesson 07 / Level 1

First Loops: Counters & Accumulators

Before you start: Input and If / Else

1. Describe a repetition

A for loop has initialization, a continuation condition and an update. for (int i=0; i<5; i++) visits i = 0,1,2,3,4. The condition is checked before the body, so the loop can run zero times. A loop removes the need to copy nearly identical statements many times.

2. Follow the exact order

Initialize once, test, run the body, update, then test again. i++ adds one and i-- subtracts one. A variable declared in the for initializer is scoped to that loop. When using a loop to read N values, the body should perform one read per iteration.

3. Keep accumulated state outside

Initialize sum = 0 before the loop and add each contribution inside it. A counter often increases only when an if condition holds. Placing sum = 0 inside the body erases previous progress. Choose a wide enough type for the total even if each individual input is small.

4. Trace boundaries

Write a table showing i and sum after each iteration. A loop from 1 through N uses i <= N; indices from 0 through N-1 use i < N. Ask whether the task includes its upper bound rather than choosing a familiar pattern automatically.

Worked example · Predict, then run

main.cpp · Complete C++17 example
#include <iostream>
using namespace std;

int main() {
    int sum = 0;
    for (int i = 1; i <= 4; i++) {
        sum += i;
        cout << i << ' ' << sum << '\n';
    }
    return 0;
}

Lesson 08 / Level 1

Fixed Arrays & std::array

Before you start: First Loops

1. A fixed sequence

int a[5] = {4,1,7,2,9} creates five contiguous int elements. a[i] accesses the element at index i. int zeros[5]{} initializes all five elements to zero; int a[5]; inside a function does not. A fixed-size array is not automatically a static-storage variable: storage duration and fixed size are separate ideas.

2. Bounds are your responsibility

Valid element indices are 0 through N-1. Built-in array indexing does not perform bounds checks. Reading or writing outside the array is undefined behavior, not a normal error-handling technique. Keep the size associated with the data and test loop boundaries carefully.

3. std::array adds container features

<array> provides array<int,5>, a fixed-size value type with size(), begin(), end() and checked at(). It can be copied as a whole. A built-in array parameter commonly decays to a pointer, losing its size information; do not compute its length with sizeof inside such a function.

4. Variable input sizes

A built-in array’s bound must be a compile-time constant in standard C++. int n; cin >> n; int a[n]; is a non-standard variable-length-array extension on some compilers. Use vector<int> a(n) for input-dependent sizes. For min/max on a nonempty array, initialize from the first actual value, not an assumed zero.

main.cpp · Complete C++17 example
#include <iostream>
#include <array>
using namespace std;

int main() {

Functions, Return Values & Scope

Before you start: Arrays and Loops

1. Give an operation a name

A function declares a return type, name and parameters. int square(int n) receives an int and returns an int. Define or declare a function before a call that needs to know its signature. C++ does not allow an ordinary named function definition inside another function; lambdas are a separate feature taught later.

2. Returning is different from printing

return sends a result to the caller and ends that function call. cout writes to output but does not return the calculated value. A void function performs an action and can use return; with no value to exit early. A non-void function must return appropriately on every path that reaches its end, except main’s special implicit-zero rule.

3. By-value parameters are separate values

void change(int x) receives a copy of the caller’s int, so assigning x does not modify the caller. A string or vector passed by value has its own value too, although creating that copy may cost time and memory. Use value parameters for inexpensive values or when an independent copy is deliberately needed.

4. Scope and overloading

A local variable is visible only in its enclosing scope. A variable declared in an inner block can hide an outer variable, which often reduces clarity. Overloading permits functions with the same name and different parameter lists; a different return type alone does not distinguish overloads. Later lessons introduce references for controlled shared access.

Compiler Errors, Debugging & Undefined Behavior

Before you start: Arrays and Functions

1. Separate error categories

A syntax or type error prevents compilation. A logic error produces an incorrect answer in a valid execution. Undefined behavior means the C++ standard imposes no requirements on that execution: it may appear to work, crash or behave differently under optimization. An out-of-bounds access is not the same as a memory leak.

2. Common undefined behavior in C++17

Reading an uninitialized automatic int, overflowing a signed integer, using a dangling pointer, and accessing an array outside its valid bounds can cause undefined behavior. Do not rely on seeing random numbers or a predictable crash. The runnable examples in this course avoid deliberately executing these operations.

3. Use warnings and diagnostic tools

Compile with -Wall -Wextra -pedantic and investigate warnings. During development, AddressSanitizer and UndefinedBehaviorSanitizer can catch many issues when supported by your compiler: -fsanitize=address,undefined -g. vector::at and array::at perform bounds checking and throw out_of_range for an invalid index. operator[] generally does not provide that check. Catch a specific exception only when your program has a meaningful recovery path; do not use catching exceptions as a substitute for writing correct loop bounds.

Switch, Ternary & Branch Design

Before you start: If / Else and Logic

1. Choose among exact values

switch works with integral or enumeration values such as int menu choices and char operators. It does not directly switch on std::string in C++17. Use if / else for strings and continuous ranges. Case labels must be suitable constant expressions rather than runtime variables.

2. Understand fall-through

A matching case begins execution at its label. Execution continues into following cases unless break, return or another control transfer stops it. Multiple labels can intentionally share a body. C++17 provides [[fallthrough]] to document intentional fall-through between statements; it does not add a break.

3. A ternary produces a value

condition ? yesValue : noValue selects one expression. Only the chosen branch is evaluated. It is useful for short output decisions or assignments such as score>=60 ? "PASS" : "FAIL". Prefer if / else for complex actions; nested ternaries can hide the logic.

4. Decide whether branches are exclusive

An if / else chain picks at most one category. Separate if statements can print several applicable labels. Before implementing, ask whether a result can belong to more than one category. For calculators, each operator selects one operation, so switch fits naturally.

While, Do-While & Sentinel Loops

Before you start: First Loops

1. Repeat while a condition remains true

A while loop checks before entering its body and before each later iteration. It is useful when input or changing state determines when to stop. Identify what changes toward termination. A condition that stays true forever produces an infinite loop unless an explicit break exits it.

2. Read sentinel input safely

A sentinel marks the end and normally is not processed as ordinary data. Read a value, test the sentinel, then update the result. while (cin >> x && x != -1) also stops on input failure. Unlike blindly using while(true), this form does not keep processing an old value after end-of-file.

Range-Based For, Nested Loops & Control

Before you start: Arrays and Loops

1. Value versus reference iteration

for (int x : a) copies each int into a local variable. Assigning x does not modify the array. for (int& x : a) binds a reference to each element so assignments affect the original. for (const auto& x : items) reads elements without copying them and prevents modification through x.

2. Use indices when positions matter

An indexed loop is useful for neighbors, reverse traversal, or changing an element by position. Range-based for is convenient when the position is irrelevant. Do not modify a container’s size during a range-based loop unless the specific operation and iteration scheme are known to remain valid.

3. Nested repetition

An outer loop can select a row and an inner loop a column. The inner loop starts again for every outer iteration. R rows and C columns mean R*C body executions; two full N loops nested usually mean O(N²). A newline after the inner loop separates printed rows.

4. Break and continue

break exits the nearest enclosing loop. continue skips the rest of the current iteration. In a for loop, the update expression still runs after continue. In a while loop, a continue that bypasses the only update can cause an infinite loop. Trace which loop each statement controls.

vector: Size, Capacity & Safe Changes

Before you start: Fixed Arrays and Loops

1. A resizable contiguous container

vector<int> v creates an empty vector; vector<int> v(n,0) creates n zero-valued elements. push_back appends and pop_back removes the last element. v.size() counts current elements and v.empty() checks whether there are none. front, back and pop_back require a nonempty vector.

2. Size is different from capacity

capacity is allocated room, while size is the number of constructed elements you may access. reserve(100) requests room without making the vector contain 100 elements. resize(100) changes its size. Writing v[0] after only reserve on an empty vector is invalid even if memory was allocated.

3. Costs and invalidation

Index access is O(1); push_back is amortized O(1), but a growth reallocation can cost O(N). Reallocation invalidates pointers, references and iterators to elements. Insertion/erasure away from the end shifts elements and costs O(N), invalidating affected positions. Do not retain an element reference across arbitrary growth.

4. Filter without skipping values

For a beginner-friendly filter, append accepted values to a new vector or filter as input arrives. A forward erase loop can skip values because later elements shift left. The erase-remove idiom is another option taught with STL algorithms. Use at for checked access when debugging and [] when your bounds are established.

String Algorithms & Character Processing

Before you start: Strings and Loops

1. Traverse text as a sequence

for (char ch : text) reads characters by value. Use char& when replacing characters in place. A string can grow with push_back or +=, and reserve can reduce reallocations when the result size is known. Unlike Java, std::string is already mutable; a separate StringBuilder type is not required for basic appending.

2. Reverse and compare

reverse(s.begin(),s.end()) changes a string in place. To preserve the original, copy it first. A palindrome equals its reverse, although a two-pointer comparison can avoid a copy. These examples operate on ASCII; reversing UTF-8 bytes directly can break multibyte characters.

3. Group adjacent equal characters

Run-length encoding keeps a current group and its count. When the character changes, output the previous group and start a new one. Remember to output the final group after the loop. Equal letters in separate groups must remain separate because the encoding describes order, not total frequency.

4. Tokens within a line

istringstream from <sstream> reads tokens from an existing string using >>. It is useful after getline when one record contains multiple fields. This is whitespace tokenization, not a general CSV parser; quoted fields and embedded separators require explicit rules.

set, unordered_set & Distinct Values

Before you start: vector

1. A set keeps unique keys

Both set<int> and unordered_set<int> keep at most one copy of each key. insert adds a key, erase removes it, count checks membership, and size counts distinct keys. For these unique-key containers count is either zero or one. C++17 does not have their later contains member; use count or find.

2. Sorted versus hashed

std::set iterates in sorted order and offers O(log N) lookup, insertion and erasure. unordered_set iterates in unspecified order and offers average O(1) lookup/insertion under suitable hashing, with linear worst cases possible. Do not present hash-table operations as unconditional constant time.

3. Distinct ranking is not frequency

A set removes repeated values, so it can identify distinct rank positions such as the third-highest distinct score. But it does not preserve how many students received that score. Keep the original scores or a separate frequency table when counts are required.

4. Recognize duplicate insertion

insert returns a pair whose second member indicates whether insertion happened. If insertion fails, the key was already present. Store repeated values in another set to report each repeated value once. Choose a sorted set when output order matters more than average hashing speed.

Random Numbers & Reproducible Experiments

Before you start: Loops and Arrays

1. Separate engine from distribution

<random> provides engines such as mt19937 and distributions that map engine output into a requested range. mt19937 rng(42) starts a pseudorandom engine with a fixed seed. uniform_int_distribution<int> die(1,6) describes an inclusive integer range. Calling die(rng) generates one roll.

2. Use a seed while debugging

The mt19937 engine sequence is specified, but a distribution’s mapping can differ between standard-library implementations. Do not assume identical die rolls across every library. A fixed seed is still useful for repeatable tests in the same environment. Randomness does not excuse an incorrectly handled boundary.

3. Avoid naive modulo habits

rand()%6+1 is a familiar pattern but can introduce modulo bias, and rand has limited statistical quality. Prefer a suitable engine/distribution pair for classroom simulations. Neither mt19937 nor ordinary classroom pseudorandom generation should be used for security tokens or passwords.

4. Test invariants

Random output need not have one fixed expected sequence. Check that every die roll lies in 1–6 and that face frequencies sum to the number of trials. An experiment with more trials often gives a better estimate of a probability, but random testing alone does not prove algorithm correctness.

References, const & Parameter Design

Before you start: Functions and vector

1. A reference is an alias

int& ref=x binds ref to the existing x. Assigning ref changes x; it does not create an independent int. A reference must be initialized and cannot later be rebound to another object. In a function parameter, T& allows the function to modify the caller’s object.

2. Read without copying

const vector<int>& values refers to the caller’s vector without copying its elements and prevents modification through this parameter. This is a useful default for read-only access to large existing strings, vectors and structs. Passing a small int by value is usually clearer than adding a reference everywhere.

3. Pass-by-value is sometimes correct

A function that needs an independent working copy can deliberately accept by value. Copying a vector<int> from an existing lvalue is linear in its size, but moves and compiler optimizations make blanket claims about every call inaccurate. Choose the parameter type from ownership and mutation needs, then consider performance.

4. Returning references requires valid lifetime

A reference returned to a local automatic variable dangles after the function returns. Do not return such references. Returning a value is safe and often optimized efficiently. const prevents changes through a particular access path; it does not make an unrelated non-const alias unable to modify the same object.

Pointers, nullptr & Safe Address Use

Before you start: References and Scope

1. Store an address

int* p=&x stores the address of x. &x obtains an address; *p dereferences a pointer to access its target. These symbols have different meanings in declarations and expressions: int& is a reference declaration, while &x is address-of. A pointer can be reassigned to point to another object.

2. A pointer may point to nothing

Initialize an optional pointer with nullptr, not an uninitialized value. Check p!=nullptr before dereferencing, but remember that a non-null pointer can still be dangling or otherwise invalid. A null check alone does not establish lifetime or bounds safety.

3. Array positions and one-past-the-end

A built-in array often converts to a pointer to its first element. Within that array, p+i points i elements ahead. A pointer one past the array’s end may be used as a traversal boundary but must not be dereferenced. Arbitrary pointer arithmetic outside the same array object is not a general navigation mechanism.

4. const and lifetime

const int* p means the int cannot be changed through p; int* const p means the pointer cannot be reassigned. Objects must remain alive while accessed. A pointer into a vector may dangle after reallocation. Prefer references, indices and owning containers when raw pointer manipulation is not required.

Before you start: Functions and References

1. Group related fields

A struct Student can hold a name and score together, avoiding separate parallel arrays that might become mismatched. A struct and class have the same core capabilities; their default access differs: public for struct, private for class. Both can contain constructors, fields and member functions.

2. Construct valid objects

A constructor has the class name and no return type. Member initializer lists initialize fields before the constructor body. Private fields restrict direct outside access; methods can enforce rules such as non-negative balances or valid score ranges. Public methods describe the actions callers are allowed to perform.

3. const member functions

A member function with a trailing const promises not to modify the object’s ordinary data members through this. For example, int getScore() const can be called on a const Student. This is different from a const return value or a const parameter. Use const to document and enforce read-only operations.

4. Value semantics and inheritance

Objects stored in vector<Student> are values and normally copy with their fields; pointers to objects do not automatically own them. C++ also supports inheritance, virtual functions and override for runtime polymorphism. Use a virtual destructor in a polymorphic base intended for deletion through a base pointer, and prefer composition when the relationship is has-a rather than is-a.

1. Tie resources to object lifetime

RAII means a resource is acquired and released through an object’s lifetime. vector manages its allocation, string manages its storage, and a file stream closes its file when destroyed. Local objects are normally destroyed when their scope ends, including during exception unwinding. This reduces manual cleanup paths.

2. Prefer owning types over raw new/delete

For ordinary dynamic sequences, use vector. When one dynamically allocated object needs exclusive ownership, unique_ptr from <memory> can own it and destroy it automatically. make_unique<T>(...) constructs that ownership safely. A raw pointer can be useful as a non-owning view, but the code must not confuse viewing with owning.

3. Moves transfer resources when supported

unique_ptr cannot be copied because two exclusive owners would contradict its contract. Moving transfers ownership to a new unique_ptr, leaving the old unique_ptr empty. std::move is a cast that enables move overloads; it does not itself move a resource or guarantee every type’s moved-from state is empty.

4. Use moved-from objects only as allowed

Moved-from standard-library objects generally remain valid with a specified or unspecified state depending on the type. Reassign or destroy them safely, but do not assume their old contents remain. A moved-from unique_ptr is specifically null. Prefer the rule of zero: let existing owning members manage cleanup rather than writing manual destructors and copy logic.

map, unordered_map & Frequency Tables

Before you start: Sets and References

1. Associate keys with values

A map stores one value per key. map<string,int> keeps keys in sorted order with O(log N) operations. unordered_map<string,int> uses hashing with average O(1) lookup/insertion and possible linear worst cases. The standard specifies behavior and complexity, not a mandatory red-black-tree implementation for every map.

2. operator[] may insert

counts[word] creates a missing key with a value-initialized int of zero, making counts[word]++ useful for frequencies. But phonebook[name] in a supposedly read-only query can insert a missing name. Use find to check without insertion, or at when absence should raise an exception.

3. Iterate over key-value pairs

A map entry is a pair containing a const key and its value. for (const auto& [key,value] : table) uses C++17 structured bindings to read it clearly. For deterministic output from an unordered_map, collect and sort keys or copy into an ordered map.

Assigning Partners needs more than storing each student’s chosen partner. No student may pair with themselves, and if A maps to B then B must map back to A. Lookups should verify existence before comparing. Building the full mapping before validation makes checks independent of input order.

Before you start: Nested Loops and vector

1. A vector of rows

Fast I/O & Stream Discipline

Before you start: cin and Loops

1. Disable unnecessary synchronization

ios::sync_with_stdio(false) allows C++ streams to operate independently of the C stdio streams. Call it before input or output. This often reduces overhead substantially on large contest inputs, but does not promise a universal speed multiplier.

2. Untie input from output

cin.tie(nullptr) removes the default automatic cout flush before cin reads. For batch judges this is normally desirable. For interactive programs, a prompt may need cout << flush before waiting for input, otherwise it can remain buffered. Understand the behavior instead of memorizing two magic lines.

3. Do not mix incompatible habits

After disabling synchronization, avoid mixing cin/cout with scanf/printf on the same streams. Use one I/O family consistently. Prefer '\n' over endl for a large volume of batch output because endl flushes each time.

4. Algorithmic cost still dominates

Fast I/O cannot make an O(N²) pair scan suitable for N=200000. First choose a viable algorithm, then reduce stream overhead. Use long long for totals that can exceed int and avoid storing every output line unnecessarily if streaming is sufficient.

Prefix Sums & Range Queries

Before you start: vector and long long

1. Define the prefix precisely

For a zero-based array, prefix[i] means the sum of its first i elements. prefix[0]=0 and prefix[i+1]=prefix[i]+a[i]. Allocate N+1 entries. This extra empty prefix handles a range beginning at the first element without an exceptional formula.

2. Subtract unwanted earlier elements

For an inclusive zero-based range [left,right], sum=prefix[right+1]-prefix[left]. The first prefix includes everything through right, and the subtraction removes everything before left. For one-based inclusive input [L,R], use prefix[R]-prefix[L-1] on the same prefix representation.

3. Preprocess for repeated questions

Building the prefix takes O(N) time and memory. Each query is O(1), giving O(N+Q) total for Q range queries. Repeatedly scanning each queried range could cost O(N*Q). Negative array values do not invalidate the subtraction formula.

4. Handle updates and numeric limits

Use vector<long long> when many int-sized values can accumulate. A normal prefix array is best for unchanged data; changing a single element would affect all later prefixes. Offline range additions can use a difference array, while interleaved updates and queries may need a Fenwick or segment tree.

STL Algorithms, Iterators & Lambdas

Before you start: vector and Objects

1. Algorithms consume ranges

Most STL algorithms use [first,last), including first and excluding last. v.begin() points at the first element and v.end() is one past the last. Never dereference end. sort needs random-access iterators, so it works on vector but not directly on set iterators.

2. Useful standard algorithms

sort orders elements; reverse reverses a range; count counts equal values; find returns the first match or end; accumulate in <numeric> computes a total. The initial value of accumulate determines its accumulation type, so use 0LL for a long long sum rather than 0 when needed.

3. A comparator means comes before

A lambda such as [](int a,int b){return a>b;} sorts descending. Comparators must define a strict weak ordering: a value must not come before itself, so <= or >= is usually incorrect. For ties, compare a secondary field. Do not use a-b as a boolean comparator; nonzero does not mean the intended order.

4. Erase-remove and iterator validity

remove_if rearranges retained elements and returns the new logical end; it does not shrink the vector. Erase the returned tail with v.erase(newEnd,v.end()). Sorting changes which value is at a position, and erasing shifts elements. Keep iterator and reference validity in mind whenever a container changes.

stack, queue, deque & priority_queue

Before you start: STL Containers

1. Stack: last in, first out

stack<int> uses push to add, top to inspect and pop to remove the newest value. pop returns void, so read top before popping. Check empty before top or pop. Stacks fit nested brackets, undo operations and iterative DFS.

2. Queue and deque

queue<int> removes the oldest item, using push, front and pop. A deque supports efficient insertion and removal at both ends through push_front, push_back, pop_front and pop_back. Queue order is essential for BFS layers. Using a stack instead changes exploration order.

3. Priority queue selects an extreme

priority_queue<int> is a max-heap by default in C++, unlike Java and Python’s common min-heap defaults. A min-heap can be declared priority_queue<int,vector<int>,greater<int>>. top is O(1); push and pop are O(log N). Its internal order is not a fully sorted vector.

4. Choose the access discipline

If the next item depends on arrival order, choose a queue. If it depends on nesting or most recent work, choose a stack. If it depends on minimum or maximum priority, choose a heap. Empty-container access is not a safe way to detect termination; inspect empty explicitly.

BFS: Unweighted Shortest Paths

Before you start: Queues and Grids

1. Explore in distance layers

Breadth-first search processes the start at distance zero, then cells one move away, then two moves away. A FIFO queue preserves this order. When every allowed move has equal cost, the first discovery of a cell gives the minimum number of moves needed to reach it.

2. Store undiscovered distances

Initialize a distance grid to -1, set the start to zero, and enqueue it. For each dequeued cell, inspect valid open neighbors. Assign dist[next]=dist[current]+1 before enqueueing. This marking order prevents repeated enqueues of the same cell from several neighbors.

3. Represent a state compactly

queue<pair<int,int>> stores row/column states. auto [r,c]=q.front() copies the front pair into structured bindings, then q.pop() removes it. Do not bind a reference to the front and use that reference after pop, because its element has been removed.

4. Complexity and limits

With four neighbors per cell, grid BFS takes O(R*C) time and memory. On an adjacency-list graph it takes O(V+E). A blocked start or target is unreachable. If weights differ, ordinary BFS is not generally a shortest-cost algorithm; Dijkstra handles non-negative edge weights later.

Worked example · Predict, then run

main.cpp · Complete C++17 example
#include <iostream>
#include <vector>
#include <queue>
#include <utility>
using namespace std;

int shortestPath(const vector<vector<int>>& grid) {
    int rows = static_cast<int>(grid.size()), cols = static_cast<int>(grid[0].size());
    if (grid[0][0] == 1 || grid[rows - 1][cols - 1] == 1) return -1;
    vector<vector<int>> dist(rows, vector<int>(cols, -1));
    queue<pair<int, int>> q;
    int dr[] = {-1,1,0,0}, dc[] = {0,0,-1,1};
    dist[0][0] = 0; q.push({0,0});
    while (!q.empty()) {
        auto [r,c] = q.front(); q.pop();
        for (int d = 0; d < 4; d++) {
            int nr = r + dr[d], nc = c + dc[d];
            if (nr >= 0 && nr < rows && nc >= 0 && nc < cols
                && grid[nr][nc] == 0 && dist[nr][nc] == -1) {
                dist[nr][nc] = dist[r][c] + 1;
                q.push({nr,nc});
            }
        }
    }
    return dist[rows - 1][cols - 1];
}

Recursion, DFS & Flood Fill

Before you start: Functions, Grids and Stacks

1. Reduce a problem toward a base case

A recursive function calls itself on a smaller subproblem. sumTo(n)=n+sumTo(n-1) reaches base sumTo(0)=0. Every recursive chain needs progress toward a stopping condition. Each active call uses call-stack space, so a deep recursion can exhaust available stack memory.

2. DFS goes deep before trying alternatives

Depth-first search explores along a path and then returns or pops back to try remaining neighbors. A visited set prevents cycles from repeating forever. DFS finds reachability and connected components, but its first discovered route need not be shortest.

3. Iterative DFS avoids deep call chains

Use a stack of states and mark a neighbor when pushing it. This keeps each state from being pushed repeatedly. The stack container uses dynamically managed memory and is often safer than hundreds of thousands of recursive calls in contest environments.

4. Flood fill measures connected regions

Scan the grid for an unvisited open cell, begin a traversal and count every reachable open cell. This count is one room or island size. Continue the outer scan to find separate regions. In Floor Plan, sort room areas and spend flooring on smaller rooms first; exact equality between remaining flooring and a room’s area is enough to cover that room.

Big O, Constraints & Algorithm Choice

Before you start: Loops and STL

1. Describe growth rather than exact seconds

Big O summarizes how work grows with input size. O(1) stays bounded, O(log N) repeatedly shrinks a search space, O(N) scans, O(N log N) often appears in efficient sorting, and O(N²) often compares all pairs. Hardware, constants and implementation still affect actual runtime.

2. Count nested and sequential work

Two consecutive N-iteration loops do 2N work, still O(N). Two nested full N loops do N². A triangular loop over pairs i<j performs N(N-1)/2 iterations, also O(N²). A counter repeatedly halved or doubled usually yields logarithmic iterations.

3. Use the largest constraints early

For N=200000, there are about 20 billion unordered pairs. That warns against naive pair checking under ordinary contest limits. Consider sorting, hashing, prefix sums or another structural improvement before tuning I/O. A rough operation budget is a planning aid, not a guaranteed machine benchmark.

A vector<int> stores contiguous ints, but maps, nodes and nested containers add overhead. Recursive calls also consume memory. State an invariant explaining why the method preserves what you need. Binary Search & Bounds

Before you start: Sorting and Big O

1. Discard half using order

In sorted ascending data, comparing the middle element with a target tells you which side can contain the desired boundary. For the first value >=target, if a[mid]<target, every earlier value is too small too. This ordered structure justifies discarding half the range.

2. Use a half-open search interval

Keep candidate positions in [left,right), initially [0,N). Set mid=left+(right-left)/2. If a[mid]<target, use left=mid+1; otherwise right=mid. Each iteration shrinks the interval. When left==right, that position is the lower bound.

3. Know the STL return values

lower_bound returns the first iterator with value>=target; upper_bound returns the first with value>target. Either may return end. Subtract begin to obtain a vector index. binary_search returns a boolean existence result. The range must satisfy the required partitioning; sorted order is the usual sufficient condition.

4. Duplicates and complexity

The difference upper_bound-lower_bound counts occurrences of a target in a sorted vector. These algorithms use logarithmic comparisons; on a vector, iterator movement is also efficient. For ordered set/map containers, use their member lower_bound for logarithmic tree navigation instead of assuming the generic algorithm has the same traversal cost.

Two Pointers & In-Place Compaction

Before you start: Sorted Vectors

1. Move indices with a proof

Two pointers tracks two positions instead of considering every pair. They may approach from opposite ends or serve as read/write positions. The important part is proving why moving a pointer does not discard a candidate that still needs checking.

2. Pair sum in sorted data

Compare a[left]+a[right] with target. If too small, increase left: using the same left with an even smaller right cannot help. If too large, decrease right: using the same right with an even larger left cannot help. Stop when left>=right if two distinct indices are required.

3. Linear after sorting

Each pointer moves in one direction at most N times, so the scan is O(N). If you sorted first, include O(N log N) sorting time. Sorting changes original indices; preserve value/index records or use a hash map when the task asks for original positions.

4. Compact with read and write

For a sorted vector, read visits every value and write counts retained unique values. If the current value differs from the last retained value, assign it at the write position and advance write. Resize only after traversal so the loop’s range remains stable.

Sliding Windows

Before you start: Two Pointers and Sums

1. A window is a contiguous segment

Adjacent fixed-length windows share most values. Instead of recomputing each sum, add the incoming value and subtract the outgoing one. A window must be contiguous; choosing the largest K values anywhere is a different problem.

2. Find a maximum length-K sum

Assume 1<=K<=N. Sum the first K values and initialize best to that sum, not zero. Slide the right boundary from K onward, updating the sum with a[right]-a[right-K]. This takes O(N) time and O(1) extra space and works even when values are negative.

3. Variable length under a sum limit

For non-negative values and a non-negative limit, extend right and then shrink left while the sum is too large. Once valid, update the best length. Removing a non-negative leftmost value can only decrease or preserve the sum, which is the monotonic property this method needs.

4. Do not ignore negative numbers

If values can be negative, removing the leftmost value can increase the sum and an invalid window might later become valid after adding a negative value. The simple variable-window rule is then not generally correct. Identify assumptions before transferring a template.

Difference Arrays & Offline Updates

Before you start: Prefix Sums

1. Record where an effect starts and stops

If many operations add a value to a whole interval, updating every element separately can be expensive. A difference array records the change at each boundary. Prefix accumulation later reconstructs the combined effect at every position.

2. Use inclusive endpoints consistently

For a zero-based inclusive update [L,R] adding V, apply diff[L]+=V and diff[R+1]-=V. Allocate N+1 entries so a range ending at N-1 can write its cancellation marker at N. That final marker is not itself a result element.

3. Reconstruct active additions

Scan positions from zero through N-1, accumulating running+=diff[i]. running is the total addition active at position i. If the original array was not all zero, the final value is original[i]+running. Use long long when update amounts can accumulate beyond int.

4. Understand the offline tradeoff

Q boundary updates and one reconstruction take O(N+Q) time. This is ideal when final values are needed after all updates. If queries must be answered between updates, rebuilding after every query loses the advantage and a more dynamic data structure may be appropriate.

Before you start: Sorting and Complexity

1. A local choice needs global justification

A greedy algorithm makes a choice and does not revisit it. A convenient rule is not enough: explain why some optimal solution can contain that choice. Try to construct a counterexample before trusting a rule on all inputs.

2. Select maximum non-overlapping intervals

When all intervals are worth one point, sort by finish time and take an interval if its start is at least the last selected end. These examples use half-open intervals [start,end), so touching endpoints are allowed. The earliest finish leaves room for future choices.

3. Use an exchange argument

Take any optimal schedule’s first interval. Replacing it with the earliest-finishing available interval cannot block any later selected interval because it ends no later. The same number of intervals still fits. Repeat this argument after the chosen interval to justify the entire greedy process.

Earliest finish does not directly solve weighted interval scheduling, where intervals have different values. Largest-coin-first also fails for denominations {1,3,4} and amount 6: it uses 4+1+1, while 3+3 is better. A different objective or input structure can require dynamic programming.

1D Dynamic Programming

Before you start: Arrays, Functions and Big O

1. Give each state an exact meaning

Dynamic programming stores answers to overlapping smaller problems. dp[i] could mean ways to reach step i, minimum cost to reach it, or best score using the first i items. Do not copy a recurrence before defining what its values represent.

2. State, base, transition and order

For climbing with one- or two-step moves, dp[i] counts ways to reach i. Set dp[0]=1 for the empty route. Reaching i comes from i-1 or i-2, so add those existing states. Fill increasing i because both dependencies have smaller indices.

3. Minimum coins instead of greedy

For unlimited positive coin values, dp[x] is the minimum number forming amount x. dp[0]=0 and unreachable amounts start at a large sentinel. Try every coin c<=x and improve with dp[x-c]+1. This considers possible final coins rather than committing to the largest one first.

4. Limits and optimization

For amount A and K coin types, the simple algorithm is O(A*K) time and O(A) memory. Counts of ways can grow beyond long long; use the problem’s requested modulus or a suitable big-integer approach when needed. C++17 does not provide a standard arbitrary-precision integer type. 2D DP: Grid Paths & LCS

Before you start: 1D DP and Matrices

1. Use two independent coordinates

A grid state uses row and column; a longest-common-subsequence state uses positions in two different strings. The dimension comes from the information needed to identify a subproblem. A 2D input alone does not automatically require DP, and a 2D DP need not represent a physical grid.

2. Count right/down grid paths

For an open cell, paths come from the cell above and the cell to the left. A blocked cell has zero paths. Initialize an open start to one, and do not overwrite that base accidentally. Fill row by row so required neighbors have already been processed. This counts paths rather than finding BFS distances.

3. Subsequence versus substring

A subsequence may skip characters but preserves order; a substring is contiguous. Let dp[i][j] be the LCS length of the first i characters of a and first j characters of b. Matching last characters give dp[i-1][j-1]+1; otherwise take max(dp[i-1][j],dp[i][j-1]). Empty prefixes have length zero.

4. Estimate the state space

A basic LCS table takes O(A*B) time and memory. A grid DP takes O(R*C). Some final-value-only problems can keep one or two rows to reduce memory, but start with the full table to understand dependencies. Large path counts can overflow signed long long, so respect the task’s counting rules.

Dijkstra: Non-Negative Weighted Paths

Before you start: BFS and priority_queue

1. Costs change the exploration order

When edges have unequal non-negative costs, fewer edges need not mean a cheaper path. Dijkstra repeatedly processes the currently smallest known distance using a min-heap. Its correctness relies on non-negative weights; it is not a general replacement for algorithms handling negative edges.

2. Relax a directed edge

Initialize source distance to zero and all others to INF. For an edge u→v with weight w, compare dist[u]+w with dist[v]. If smaller, update dist[v] and push the new candidate into the heap. Store edges as destination/weight pairs in adjacency lists.

3. Skip outdated heap entries

A vertex may get a better distance after an older candidate was pushed. Removing arbitrary entries from priority_queue is inconvenient, so keep both and skip a popped pair when its distance differs from the current dist[vertex]. This is lazy deletion, not a reason to mark a vertex final at its first insertion.

4. Complexity and numeric range

With a lazy binary heap, at most O(E) candidates are inserted, giving O((V+E) log(E+2)) time and O(V+E) memory; common simple-graph summaries use O((V+E) log V). Choose INF above every valid path cost and below the arithmetic limit. The examples assume candidate sums remain below INF.

main.cpp · Complete C++17 example
#include <iostream>
#include <vector>
#include <queue>
#include <utility>
#include <functional>
using namespace std;

const long long INF = 4000000000000000000LL;
vector<long long> dijkstra(const vector<vector<pair<int,int>>>& graph, int source) {
    vector<long long> dist(graph.size(), INF);
    priority_queue<pair<long long,int>, vector<pair<long long,int>>, greater<pair<long long,int>>> heap;
    dist[source] = 0; heap.push({0,source});
    while (!heap.empty()) {
        auto [distance,u] = heap.top(); heap.pop();
        if (distance != dist[u]) continue;
        for (const auto& [v,weight] : graph[u]) {
            if (distance + weight < dist[v]) {
                dist[v] = distance + weight;
                heap.push({dist[v],v});
            }
        }
    }
    return dist;
}

Disjoint Set Union: Connectivity

Before you start: Vectors and Functions

1. Maintain groups that merge

Disjoint Set Union represents a partition into connected groups. Initially each vertex is its own group. find(x) returns a representative root, and unite(a,b) merges the two groups if they differ. Two vertices are connected exactly when their representatives match.

2. Parent links and path compression

parent[root]=root identifies a root. Following parent links reaches it. Path compression shortens future searches by making visited nodes point closer to the root. The iterative implementation here uses path halving: redirect a node to its grandparent while climbing.

3. Union by size

After finding two roots, attach the smaller component under the larger one and update the stored size at the surviving root. This keeps trees shallow. Component sizes should be read from representatives, not arbitrary nodes whose stored size may no longer describe a whole component.

4. What DSU can and cannot answer

With compression and union by size, operations are amortized O(alpha(N)), where inverse Ackermann grows extremely slowly. DSU supports incremental undirected connectivity, not route reconstruction or ordinary edge deletion. A failed union means the endpoints were already connected; that can help detect a cycle when adding an undirected edge.

Worked example · Predict, then run

main.cpp · Complete C++17 example
#include <iostream>
#include <vector>
#include <numeric>
#include <utility>
using namespace std;

class DSU {
    vector<int> parent, size;
public:
    explicit DSU(int n) : parent(n), size(n,1) { iota(parent.begin(), parent.end(), 0); }
    int find(int x) {
        while (parent[x] != x) { parent[x] = parent[parent[x]]; x = parent[x]; }
        return x;
    }
    bool unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return false;
        if (size[a] < size[b]) swap(a,b);
        parent[b] = a; size[a] += size[b];
        return true;
    }
    int componentSize(int x) { return size[find(x)]; }
};

int main() {
    DSU groups(5);
    groups.unite(0, 1);
    groups.unite(1, 2);
    cout << boolalpha << (groups.find(0) == groups.find(2)) << '\n';
    cout << (groups.find(0) == groups.find(4)) << '\n';
    cout << groups.componentSize(1) << '\n';
    return 0;
}
